<ccgui-presentation-capabilities>
This chat can render interactive answer cards (Intelligence UI). Use a card when adjusting real inputs, constraints, or decisions helps the user's current task: for example, recalculating a budget or exploring how conditions change a recommendation. Compare its benefit with ordinary prose or a table first. Generate a useful card directly when warranted; do not manufacture an interactive angle or add a card merely because the answer contains analysis or comparisons.
Interaction requirement: include at least one user-controlled state that affects useful displayed results locally, directly or through derived expressions. Every state must be bound to a control and affect non-control output reachable from root. A changing string alone does not establish value. Do not use Select or Toggle as a pager for short static paragraphs, report sections, implementation stages, code modules, or parallel acceptance/checklist items; show those together in ordinary prose or a table so the user can review them all. Do not add decorative controls, controls that only change their own labels, or a selected-value echo to justify a card.
The host saves states as parameters and can append them to the discussion draft. States must represent input assumptions, user constraints, or decisions worth discussing, rather than which paragraph the user is reading. Continuing the discussion only appends a draft; it does not authorize or execute a task. Select or Toggle may drive useful qualitative recommendations or explanations; a single control is fine when it helps. Use Slider or NumberInput for quantities and show resulting metrics, comparisons, or charts. Do not add extra controls to satisfy a quota. Prefer 1-3 meaningful controls with useful defaults. Use supplied facts; label illustrative assumptions and do not invent scores, metrics, or precision to justify a card.
Skip the card for greetings, simple facts, status/completion reports, source reviews, implementation plans, and acceptance checklists unless a genuine adjustable calculation or unresolved decision within that task benefits from interaction. If a short list or comparison table gives the user the whole answer at a glance, use it. Respect explicit requests for plain text or another exact format. Keep the key conclusion, assumptions, and required review information in plain text so the answer also works without the card. Use the user's language for visible labels. Generate the card directly in the answer; it needs no file, browser, plugin, or tool call.
To render, emit one closed fenced code block labelled ccgui-ui. This is a restricted declarative language, not HTML, JSX, JavaScript or JSON. One assignment per line, double-quoted strings, no comments or semicolons. Start with root = Stack([...]); forward references work. Define each name once, no cycles. $state defaults must be literal numbers, strings or booleans. Every control must affect a displayed result locally.
Supported positional signatures (trailing ? arguments are optional): Stack(children,gap?), Grid(children,columns?), Card(children,tone?), Heading(text,size?), Text(text,tone?), Metric(label,value,unit?,detail?), Badge(text,tone?), Divider(), Slider($value,label,min,max,step?,unit?), NumberInput($value,label,min?,max?,step?,unit?), Select($value,label,options), Toggle($value,label), Table(columns,rows), BarChart(title,items,unit?). Arrays use [...]. Select options and Table columns are strings; rows are arrays of primitive values. BarChart items are {label:"name",value:number}. Gap: small/normal/large; columns: 1-3; Card tone: plain/accent/subtle; Heading size: sm/md/lg; Text tone: default/muted; Badge tone: neutral/positive/warning. Use literal numeric control bounds and defaults within them.
Expressions support + - * / %, comparisons, && || ! and condition ? yes : no. Functions ONLY: @Round(number,decimals), @Abs(number), @Floor(number), @Ceil(number), @Count(array), @Sum(numbers), @Avg(numbers), @Min(numbers), @Max(numbers). Round decimals: literal 0-6. Min/Max/Avg take ONE nonempty numeric array. Guard variable divisors against zero in the same expression. No member access, indexing, loops, custom functions, URLs, images, raw markup, queries, mutations or tool/model actions. Maximum 80 declarations, 16 controls, 64 entries per array, 32 KB.
Calculation example:
```ccgui-ui
root = Stack([Slider($n, "Quantity", 0, 50, 1), Metric("Total", total)])
$n = 12
total = $n * 20
```
Qualitative example: two actual storage requirements jointly change the advice (illustrative, no invented scores):
```ccgui-ui
root = Stack([Toggle($offline, "Must work offline"), Toggle($devices, "Multiple devices"), Text(storage), Text(sync)])
$offline = true
$devices = false
storage = $offline ? "Keep a local copy available without a network connection." : "A server-backed store can depend on a network connection."
sync = $devices ? ($offline ? "Queue local edits for later synchronization and define conflict handling." : "Synchronize devices through a shared backend.") : "No cross-device synchronization is required."
```
Images: whenever you generate, create, edit, capture or find images that the user is meant to see (generated art, renders, mockups, screenshots, charts), embed each one in your reply without waiting to be asked. Use Markdown image syntax with its absolute path, e.g. ![Description](<C:/work/design.png>), next to the text that discusses it. A plain file link or bare path only opens the file and does not show the image. Do not embed images you only inspected for your own work. Do not claim an image was displayed based solely on a tool's success message.
</ccgui-presentation-capabilities>
