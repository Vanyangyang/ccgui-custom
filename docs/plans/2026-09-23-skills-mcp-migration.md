# Skills 与 MCP 设置模块迁移实施计划

日期：2026-09-23  
状态：已实施（阶段 1–5 主体落地，阶段 6 完成代码侧验证；真实桌面应用与跨平台验收未完成，见文末《实施记录》）。  

## 一、目标与已确认决策

将参考项目的 **Skills、MCP 两个模块完整地分阶段迁移**至当前项目，使用当前项目的设置框架、组件、国际化和原生能力，不复制参考项目的整个拓展中心。

**已确认的导航结构：**

```text
系统
插件
CLI 管理
CLI 未安装
CLI 未启用

能力扩展                 ← 新增独立分组
  Skills                 ← 独立页面
  MCP                    ← 独立页面

工作区与数据
  工作区
  归档管理
  用量
其他
```

- 首期支持 Claude Code、Codex；不因当前项目支持其他 CLI，就推断它们具备相同的 Skills/MCP 配置协议。
- “完整迁移”指下述各阶段全部完成，不以导航出现或静态页面完成作为交付终点。
- 保留参考项目的核心功能，但使用当前项目视觉规范，不照搬其顶部导航、全局样式和组件依赖。
- 本次文档交付只保存计划，不执行功能实现、提交或推送。

## 二、调研结论与迁移策略

### 2.1 当前项目已有的可复用能力

- 设置页面通过 `settingsRegistry` 注册，分组由 `GROUP_META` 排序；SDK 的 `group` 为字符串，因此新增分组不需要修改插件公共契约。
- 当前 IPC 已提供原生与远程 Web 访问的传输封装，新增功能应沿用该入口。
- 聊天输入已有 Skills/斜杠菜单扫描能力，应复用其引擎目录解析规则，避免设置页与聊天页识别出不同的技能集合。
- 已有内置 `ccgui-plugin-creator` Skill 安装与归属标记机制，迁移模块必须保护它，不能另建一套逻辑覆盖其文件。
- Rust 已具备 HTTP、Git、JSON、TOML、YAML、哈希等基础依赖；默认不新增依赖。
- 调研时工作区无未提交改动，所在分支为 `v1.0.8`。实施前重新检查分支与 diff，不将此记录视为持续有效的工作区状态。

### 2.2 参考项目并非两个孤立页面

**Skills：**
- 页面包含本地技能、在线发现与搜索、仓库管理、安装、导入、卸载与恢复、目标引擎同步、更新检查、使用情况等功能。
- Rust 后端已拆分为扫描、注册表、生命周期、目标同步、网络、发现和更新等模块，可以按职责选择性迁移。
- 前端依赖 vendored TokenTracker 的组件、Provider、样式和传输层，不适合直接整体复制。
- 后端默认使用 `~/.ccgui/skills`，不能不经处理就与参考项目共用可写注册表。

**MCP：**
- 参考实现同时展示配置清单和运行时信息。
- 启停写入针对参考项目支持的配置来源，不是适用于所有 CLI 的通用开关。
- Claude 运行时数据来自参考项目的会话快照；Codex 运行时查询也依赖其工作区和引擎架构。
- 当前项目不能直接复用参考项目的工作区 ID、全局配置路径和会话状态容器。

### 2.3 采用的方案

采用 **“功能与测试迁移 + 当前项目原生 UI 重建 + 引擎适配层重接”**。

不采用：
- **整页复制**：会引入第二套 UI、国际化、传输与运行时依赖。
- **仅复制视觉**：不能满足安装、同步、启停和状态查询的完整功能目标。
- **一次适配全部 CLI**：不同引擎协议和路径差异过大，超出已确认首期范围。

迁移代码时记录来源，保留已有许可证及归属信息；同时检查 vendored 部分的上游声明，不将参考项目根许可证视为所有第三方内容的唯一依据。

## 三、功能与交互设计

### 3.1 设置框架接入

- 新增 `capabilities` 分组，中文“能力扩展”，英文“Capabilities”。
- 注册 `skills`、`mcp` 两个 section，支持现有 `page` 查询参数直接定位。
- 分组排序位于全部 CLI 分组之后、“工作区与数据”之前。
- 两个页面采用懒加载，不在打开普通设置时扫描技能、联网或查询 MCP。
- 中英文标签、搜索、选中态、窄窗口布局和键盘操作沿用现有设置框架。
- 不更改现有插件设置注册逻辑与 CLI 分组展开行为。

### 3.2 Skills 页面

| 功能区域 | 迁移内容 |
|---|---|
| 我的 Skills | 列表、搜索、来源与引擎筛选、已安装数量、详情 |
| 技能详情 | 名称、描述、来源、目录、目标引擎、Markdown 内容 |
| 本地导入 | 选择目录、校验 `SKILL.md`、选择 Claude/Codex 目标 |
| 发现与搜索 | 热门、在线搜索、仓库发现、分页、缓存和失败重试 |
| 仓库管理 | 添加和移除技能来源仓库 |
| 生命周期 | 安装、卸载、短期撤销恢复、更新检查与更新 |
| 目标同步 | 按引擎启用或移除受管副本，识别丢失副本并重新同步 |
| 使用情况 | 使用统计与管理操作记录，分开展示、注明统计范围 |

**交互规则：**
- 默认进入“我的 Skills”；进入发现区域或主动搜索时才发起在线请求。
- 来源区分应用内置、本地非托管、当前应用托管、插件或系统提供。
- 内置、系统和插件管理目录默认只读；不允许通过通用删除逻辑破坏它们。
- 将“移除某个引擎副本”“卸载托管技能”“删除本地技能”区分为不同操作。
- 删除本地文件需展示实际作用路径并二次确认；不静默覆盖同名非托管目录。
- 更新如发现本地修改，阻止覆盖并展示冲突，不自动丢弃用户修改。
- 安装或卸载成功后使聊天 Skills 索引失效；不伪造当前会话已重新加载技能。
- 无法从现有数据可靠判断的使用情况显示“暂无可用数据”，不能用安装记录冒充调用次数。

### 3.3 MCP 页面

保留以下结构：

1. Claude Code / Codex 引擎页签。
2. 来源筛选、服务搜索、数量统计与刷新。
3. 配置清单与运行时清单分区。
4. 服务详情。
5. 可管理配置的启停开关。

**状态语义：**
- “配置已启用”与“运行时已连接”分开表达。
- 没有运行会话、引擎不支持查询或查询失败时，显示具体原因，不显示为“服务不存在”。
- 运行时信息关联实际引擎、工作区及会话，展示采集时间。
- 全局配置清单不依赖选中工作区；项目级配置和运行时状态使用当前工作区。
- 无活动会话时不为查看列表偷偷启动 CLI 或 MCP 服务。
- 内置动态注入的 MCP 服务标记为“内置”，不提供通用配置开关。

**配置操作：**
- 只对已实现并验证写入语义的来源开放启停。
- Claude 与 Codex 分别适配实际原生配置；不把参考项目的 `ccgui_config` 当作当前项目配置。
- 不支持安全写入的来源只读展示，并明确原因。
- 写入成功后重读配置；提示对新会话生效，除非引擎确实支持并成功完成热加载。
- 不自动停止用户正在运行的会话。
- 不扩展为 MCP 市场、OAuth 登录中心或通用配置编辑器；这些不属于本次两个页面的既有核心功能。

### 3.4 统一体验

- 使用当前项目的列表、按钮、输入框、详情面板和提示组件。
- 刷新复用现有“转圈 → 对号”反馈；安装下载使用进度反馈，不混用。
- 空列表、筛选无结果、加载失败、部分来源失败分别展示。
- 同一条目操作期间禁用重复提交，其他条目保持可操作。
- 页面切换、工作区切换和卸载后，旧请求不得覆盖新状态。
- 同步更新 UI 规范并登记新增刷新入口。

## 四、实现边界、接口与安全设计

### 4.1 模块职责

- **设置层**：导航注册、页面容器、国际化。
- **Skills 功能层**：页面、详情、列表状态、在线发现及管理操作。
- **MCP 功能层**：列表、筛选、详情、配置与运行时状态组合。
- **IPC 层**：强类型请求、响应和错误归一化，沿用当前 transport。
- **Rust Skills 后端**：扫描、注册表、文件生命周期、目标同步和网络。
- **Rust MCP 后端**：来源枚举、安全配置读写、引擎运行时查询。
- **引擎层**：目录、配置协议和运行时能力差异；UI 不直接解析 CLI 配置文件。

不修改插件 SDK；若实施发现必须改公共契约，应单列变更并执行插件文档生成及契约测试，不能顺手扩大本计划。

### 4.2 IPC 契约

Skills 保留参考后端的两个分发入口，但前端使用判别联合类型封装，避免传播 `any`：

| 入口 | 请求范围 |
|---|---|
| `skills_hub_query` | installed、discover、search、repos、popular、updates、activity、skill_usage |
| `skills_hub_mutate` | install、uninstall、restore、set_targets、import_local、delete_local、add_repo、remove_repo |

新增 MCP 接口：
- `mcp_inventory`：返回配置条目、运行时条目、来源级错误及能力信息。
- `mcp_set_enabled`：使用后端生成的条目标识、目标状态和读取版本提交变更。

**共通要求：**
- 条目标识包含引擎、来源和范围，不能只以名称定位。
- MCP 写入接口不接受前端任意指定文件路径。
- 变更接口返回实际结果，不用 `{ok:true}` 隐藏部分失败。
- 多目标 Skills 同步逐目标返回结果；只有全部成功才显示“全部同步完成”。
- 错误区分权限、格式、冲突、网络、限流和能力不支持，提供对应重试路径。
- 首期为桌面本地管理；远程 Web 页面显示本地管理提示，后端远程分发也拒绝这些新入口，避免意外开放主机文件管理能力。

### 4.3 Skills 存储与兼容

- 在当前应用自身数据目录下建立独立 `skills-hub` 存储，不共享参考项目的可写注册表。
- 保存注册表、受管原件、暂存文件、回收记录及有界缓存。
- 默认不自动导入参考项目的历史注册表；原 CLI 目录中的技能可扫描展示，用户通过导入操作纳管。
- 目录解析复用当前项目引擎规则，尊重 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 等覆盖。
- 公共目录和符号链接按真实路径识别，避免重复展示和重复删除。
- 创建副本时记录归属；卸载只移除已确认属于当前应用管理的文件。
- 在线技能只下载和解析，不自动执行技能内容或安装脚本。
- 更新先暂存、校验、再替换；失败保留旧版本。
- 路径遍历、越界符号链接和异常仓库子路径必须被拒绝。

### 4.4 MCP 配置与敏感数据

- 写入采用同路径串行化、版本冲突检测、临时文件及原子替换。
- 保留无关字段；TOML 使用已有编辑能力，避免整文件重建导致注释和结构丢失。
- 配置解析失败不写入、不重置，向用户展示错误。
- 写入失败不提前更新 UI 为成功状态。
- 日志不得输出 token、环境变量值、完整请求头或原始配置。
- 列表和详情默认脱敏 URL 查询凭据、认证头及敏感环境变量；截图示例中的 URL 不能直接照搬展示。
- 参考项目的“读取失败后仅记日志、返回空列表”等行为不原样迁移。
- 不新增常驻轮询；页面进入、手动刷新和操作完成后刷新，运行时变更利用现有会话事件。

**验收：** 有会话时展示真实观测，无会话时明确提示；不启动额外引擎、不重启用户会话、不将历史快照冒充实时状态。

- [ ] 完成中英文、深浅色、窄窗口和键盘验证。
- [ ] 更新 UI 规范、刷新入口清单与迁移来源说明。
- [ ] 运行相关测试、类型检查、构建及 Rust 静态检查。

## 六、测试矩阵与交付标准

以下为实施阶段的验证要求，不表示文档保存时已执行这些测试。

### 6.1 前端测试

- 导航位置、分组标签、搜索、直接定位及懒加载。
- Skills 安装、导入、目标同步、失败重试、恢复与冲突展示。
- MCP 引擎切换、来源筛选、搜索、刷新、详情及启停。
- 点击开关不误打开详情；同一条目不可重复提交。
- 快速切换页面、工作区和引擎时，旧请求不能串数据。
- 部分来源失败与真正空列表可区分。
- URL 和其他敏感字段脱敏。
- 远程访问入口不可执行本地管理操作。

### 6.2 Rust 与文件安全测试

所有写入测试使用临时目录，不改真实 HOME。

- 自定义引擎目录、生僻字符、中文、空格路径。
- 符号链接、重复来源、路径穿越及越界删除。
- 同名冲突、内置技能、插件技能和手工修改保护。
- 多目标部分成功、暂存失败、恢复记录失效。
- 配置启停往返、字段保留、格式错误、权限失败。
- 外部并发编辑、写入版本冲突和原子替换失败。
- 下载失败、限流、无效远端内容及更新失败。

### 6.4 真实应用验收

- Skills 变更后，新会话能按 CLI 原生规则发现技能。
- MCP 配置变更后，新会话的行为与配置状态一致。
- 未安装引擎如实提示，不擅自安装。
- 不影响聊天发送、中断、已有插件开发 Skill 和 Computer Use MCP。
- Browser 预览只验证界面，不代替 Tauri 原生文件和引擎验证。
- 以实际测试平台报告结果；未在 Windows/Linux 运行则明确列为未覆盖。

## 七、风险、默认边界与回退

| 风险 | 处理方式 |
|---|---|
| 参考代码携带整套 UI 依赖 | 只迁移业务逻辑和测试，使用当前组件重建 |
| 两个项目共同修改注册表 | 独立应用存储，不自动纳管参考项目数据 |
| 开关写入成功但引擎行为不符 | 每个来源单独验证，未验证来源只读 |
| 删除用户手工技能 | 归属校验、真实路径校验、删除确认 |
| 配置并发修改丢失 | 版本检测、串行写入、原子替换 |
| 密钥出现在页面或日志 | 服务端返回前脱敏，日志只保留错误上下文 |
| 安装状态与聊天发现不同步 | 复用目录解析并使现有索引失效 |
| 运行时状态被误读为实时 | 标注会话、采集时间和可查询能力 |

**默认边界：**
- 首期仅 Claude Code、Codex 和本地桌面管理。
- 不迁移 Plugins、Hooks、Rules、Commands、Subagents 模块。
- 不新增公共 SDK 能力，不引入整套 TokenTracker 服务。
- 不自动修改参考项目、不移动其源码、不删除其数据。
- 不进行不可逆的旧配置迁移，不重置现有 CLI 配置。

**回退原则：**
- UI 接入可独立撤回，不影响已有设置。
- 当前应用 Skills 管理数据独立保留，不通过回退程序批量删除 CLI 文件。
- MCP 恢复仅针对当前应用实际修改过的文件，并检测后续外部修改；存在冲突时停止自动恢复。
- 每阶段交付报告列出：完成能力、修改文件、实际通过测试、失败或跳过项、剩余风险。

## 二、功能覆盖

**Skills（设置 → 能力扩展 → Skills）**
- 三个页签：我的 Skills / 发现 / 使用情况；仅进入页签才发起对应请求。
- 我的 Skills：来源与引擎筛选、搜索、计数、刷新并检查更新、更新徽标、卸载（5 分钟回收站恢复）、纳管/导入、删除本地（展示实际路径并二次确认）、详情（属性、目标引擎复选、SKILL.md 内容、仓库链接）。
- 发现：skills.sh 搜索（≥2 字符）、热门（6h 缓存）、仓库发现（显式扫描）、仓库增删、安装到 Claude/Codex。
- 使用情况：Claude Code 会话转录的技能调用统计（标注统计范围、Token、最近使用）、未观察到调用的已安装技能、管理操作记录；无数据时显示「暂无可用数据」。
- 只读来源保护：内置（`ccgui-plugin-creator`）、Codex `.system`、Codex 插件缓存一律 `readonly=true`，删除/导入被后端拒绝并在 UI 说明原因。
- 本地修改保护：更新/重装前比对托管副本哈希，不一致时返回 `conflict`，UI 展示冲突并需显式确认覆盖。
- 多目标同步逐目标返回 `targetResults`，部分失败显示失败目标，不出现「全部同步完成」。

**MCP（设置 → 能力扩展 → MCP）**
- Claude / Codex 引擎页签；配置清单与运行时清单分开；来源筛选（全部/配置/运行时）、搜索、计数、刷新、详情。
- 来源：Claude `~/.claude.json`（user/local，只读）、工作区 `.mcp.json`（project，经 `.claude/settings.local.json` 启停）、Codex `$CODEX_HOME/config.toml` 与工作区 `.codex/config.toml`（`[mcp_servers.<name>] enabled`，可写）。
- 脱敏：URL userinfo 与敏感查询参数、环境变量与请求头只返回键名；不返回凭据值。
- 写入：内容哈希版本比对 + 串行化 + 原子替换，写后回读；解析失败不写入。
- 运行时：Claude 会话 `system/init` 快照（工作区/会话/采集时间，结束态标注）；Computer Use 注入服务标记为「内置」；Codex 显示「当前引擎不支持运行时查询」。

**远程 Web**：两个页面在 `isWeb` 下只渲染桌面端提示；`mcp_inventory` / `mcp_set_enabled` / `skills_hub_*` 均不在 `web/dispatch.rs` 白名单内，后端远程分发直接拒绝。

## 三、与计划的偏差

1. 新增 `skills_hub_query` 的 `skill_content` 模式（详情面板需要 SKILL.md 内容；计划的功能表要求详情含 Markdown，但 IPC 表未列此模式）。目录经相对路径净化与符号链接防护，仍不接受前端绝对路径。
2. `skills_hub_mutate` 的 `install` 新增 `force` 字段（配合计划 §3.2 的本地修改冲突保护；不带 `force` 时后端拒绝覆盖）。
3. 目标引擎首期只暴露 Claude / Codex；`agents`（`~/.agents/skills`）按参考实现保留为隐藏目标参与扫描/同步，UI 不列出。
4. Codex 只读来源（`.system` / 插件缓存）与内置技能按只读展示；参考实现会把它们当普通未托管技能处理，这是为满足计划 §3.2 的保护要求而收紧。
5. `reason` 字段不再承载可枚举状态文案（改由前端按 `status` 做中英文本地化）；`reason` 只保留给异常诊断。
6. 「纳管」（import_local）记录来源目录并保护它：同步与移除都避开用户自己的本地副本，不再像参考实现那样把来源目录替换成受管符号链接。卸载/恢复只动本应用创建的副本。
