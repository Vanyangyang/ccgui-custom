# 聊天内接力 MVP：第一性原理体检与实现边界

## 从必须成立的事实出发

1. 一条用户消息只能有一个发送消费者。插件模式与普通消息列表 / 输入框互斥挂载，不监听 DOM 按键截流。
2. “计划”是经用户授权的产物，不是模型自报的状态。模型 done 只结束一次规划轮次；只有用户对最新完整版本的确认才启动写入。
3. 只读是一种真实能力约束，不是提示词。拒绝 OMP plan-yolo 等会自行进入执行的模式；对每个规划引擎核查内置工具、扩展和外部工具通道。
4. 引擎原生会话不等于逻辑会话。Pi 规划保存自己的 sessionId；隔离 Codex 规划每轮新开原生会话并携带要求及最新计划；执行始终新建 sessionId。插件层保存逻辑关联，不篡改普通 chat store。
5. 取消是生命周期协议。记录 runId、发中断、等终态；启动尚未返回时同样必须能取消，不把按钮点击等同于进程退出。
6. 恢复不能制造第二次写入。先持久化可预测 runId 与配置快照，再启动进程；恢复后人工核对，不自动重试写节点。

## 体检发现及处理

- 已有插件 Agent API 能启动轮次，但缺少只读参数、能力目录和调用前可知的 runId：补通用 SDK 契约，由宿主强制处理。
- CLI 的 plan 名称不代表安全只读：原生层 fail closed；真正能够兑现约束才允许作为规划者。
- 插件事件可能早于 start 返回：使用调用方 32 位十六进制 requestId，由宿主形成带插件属主前缀的 runId，订阅和落盘先于启动。
- 一些 done/error 可能早于子进程真正退出：对接力主用引擎的插件事件延后终态到退出观察，避免旧执行者仍在写而新规划已开始。
- 页面退出按钮可能绕过插件自己的忙碌限制：宿主公开退出阻断回调并同步守卫退出，而不是只禁用一个视觉按钮。
- 活动草稿关闭会丢失重新寻址入口：会话身份与运行锁由宿主持久化，阻止活动标签关闭及替换草稿的引擎切换；插件暂不可用时保持恢复提示，不能静默返回普通发送。
- 磁盘失败不意味着子进程停止：启动后保存失败保留运行身份并中断，等终态才释放任务；停止请求先下发，再尽力保存取消状态，不能被磁盘故障阻断。
- 恢复控制不能依赖模型目录可用：先显示已保存记录和停止入口，再异步读取目录；目录失败不会隐藏旧任务或解开退出锁。
- 模型目录读取可能携带凭据：SDK 只返回白名单字段（ID、显示名、能力），不返回原始渠道配置、环境变量或认证内容。
- 恢复前的工作区可能已经改变：恢复一律待核对；执行提示先检查实际文件，冲突时停止。但首版没有整个工作区的跨进程互斥或内容指纹，不能声称已解决所有并发编辑问题。

## 最小实现而非通用工作流平台

宿主增加 generic conversation-mode 注册表及权限、清洗后的 Agent catalog、只读/请求身份参数；双节点状态机、交接协议、版本与 UI 均在单文件 ESM 插件内。没有新增依赖，没有设计通用 DAG，没有硬编码宿主“接力”业务状态。

插件接口可承载将来的其他会话模式。首版为了不破坏成熟聊天存储，选择独立插件记录在同一聊天区域展示；不会承诺原生聊天搜索、导出或会话标题已经包含插件记录。

## 必测失败路径

多轮规划不执行；未解决的问题不批准；草稿阻止批准；历史版本不批准；规划失败不沿用旧批准；保存失败不启动；重复点击不重复启动；早到/重复/晚到事件不污染另一轮；启动期间取消；卸载期间仍在启动的进程；恢复不自动执行；同引擎换模型与跨引擎新会话；配置目录不泄漏密钥。

## 不伪装完成

真实 UI 测试与模拟引擎测试分别报告。原生参数/进程测试不等于真实模型业务任务成功。没有实际运行的 CLI、没有真实测试的 Windows 平台，明确列为未覆盖。首版是可迭代的插件与宿主扩展，不自动提交代码、推送、部署或安装额外引擎。
