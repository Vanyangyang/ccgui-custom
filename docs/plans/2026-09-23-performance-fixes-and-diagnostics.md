# 大任务性能修复与本地诊断实施计划

用户已明确批准两步执行：先修已确认的性能问题，再加入可复制的监控日志。本轮直接实施，不提交、不推送、不修改已有无关改动，不增加依赖。

## 第一步：以回归测试约束修复

- 批量工具消息按原顺序归并，减少消息列表重复扫描/复制与重复通知；混合事件、终态、并发会话、文本与工具结果不可丢失。
- 对大过程组内部做有界展示，保留所有历史可访问；批量新增不同时播放全部入场动效。
- 优先修已可证实的问题，不凭假设改写整个 Markdown 解析器或关闭硬件加速。全文完整性不允许以裁掉思考原文换性能。

## 第二步：低开销、可解释的本地诊断

- 复用现有 sysinfo 依赖与状态栏指标，原生后台低频采样，避免 JS 卡死时连证据一起丢失；数据结构和缓存有容量限制。
- 前端只聚合数值：每批引擎事件的数量/耗时、实时渲染提交耗时、前台事件循环延迟、消息/会话数量；约 5 秒一条、最多 60 条/5 分钟，不逐 token 写日志，不在诊断中保存对话/代码/路径/凭据。
- 监控明确区分本窗口的前端指标、原生主进程/后代进程以及归属不明的 WebKit 候选；首次 CPU 未建立基线或 API 不支持时明确不可用，不能编造零值。
- 状态栏性能入口与设置「社区与反馈」提供同一个诊断弹窗；生成报告后可复制，失败保留可手工选择的文本；显示采集范围、隐私与不可归因限制。
- 无自动上传。线程/定时器/observer 有清理；不无限积累日志或不断读取完整聊天历史。

## 验收

- 工具批次功能与更新次数/工作量回归；120/500工具组挂载数量上限、翻页/展开与全文完整性。
- 数值日志容量、清理、后台不误记卡顿、脱敏/禁止任意字段、采集失败和剪贴板失败路径。
- Rust 采样分类、容量、首次 CPU 基线、缓存复用与序列化边界测试。
- 针对性前后端测试、前端构建、实际浏览器 UI 验证；报告区分局部实验与真实原生负载，不声称未经复现的整机问题彻底消失。

## 实施结果

- 连续同 run 工具段按顺序归并，其他类型事件、run/session 切换前提交；128 start + 128 args + 128 result 的回归由 384 次 store 写入变为 1 次。保留无变化消息引用，重复结果和未匹配补丁不制造新消息快照。不同 result 子串首次匹配仍需搜索工具索引，不宣称任意输入均线性。
- 过程组每页 40 项，默认最新页，读历史不被新增抢页；搜索命中能展开并跳页。大组/批量入场禁用高成本入场动画；全文不裁剪，工具参数仍延迟挂载。
- 未跟踪文件只对普通文本计数，最多读取 1MiB + 1 字节、最多精确计 100,000 行；超限、NUL 二进制、符号链接、FIFO 返回既有 unknown/Optional 统计，不伪造截断精确值。tracked diff 不变。
- 原生独立线程采样，采集后间隔 5 秒，最多 60 条/5 分钟、每条 32 进程。记录系统 CPU/内存/swap、主进程和后代进程 CPU/RSS，以及明确未归属的 WebKit 候选。为 GPU/content 各保留至多 2 槽，避免子进程过多导致这两类完全失去采样；空槽回填、选择稳定且标注遗漏数量。
- 前端每秒探测前台事件循环延迟，每 5 秒聚合窗口指标：事件/工具消息数、批处理耗时、实时提交耗时、可用时的 Long Tasks、会话及消息规模、活动尾部文本长度、已挂载过程项数。无逐 token 日志；不导出正文、路径、参数或凭据。
- 状态栏「性能」或设置「社区与反馈 → 性能诊断」打开只读快照，默认「复制诊断摘要」（不超过 12,000 UTF-8 字节，保留峰值、前五高 CPU 进程和异常附近采样）；「导出完整诊断文件」保存同一快照全部数据的紧凑 JSON。原生导出超时 2.5 秒后仍生成前端报告；剪贴板失败保留手动复制。报告是打开弹窗时的快照，需要最新记录时关闭后重开。
- 默认开启；原生偏好原子保存至应用目录的 performance-diagnostics.json（只保存开关，不保存日志）。关闭停止原生工作线程，释放 CPU 基线，停止前端 timer/observer 并清空记录/预览；工具事件诊断遍历也跳过。开关变化广播至其他窗口和 Web 客户端，旧 IPC 响应不能覆盖新状态或卸载后的状态。偏好损坏时安全关闭，不阻止客户端启动；前端读取暂时失败可重新打开弹窗重试。

## 验证实况与限制

- 初版全量 Vitest：148 文件、979 用例通过；日志过期与上下文失败标记另跑 4 文件、12 用例通过。后续五分钟/摘要/开关调整的验证另记于下方。窗口后台暂停采样不会让过期样本一直出现在导出中；上下文采集失败明确标为不可用。
- Node 流式/Markdown 回归：39 通过。
- Rust：Git 33、metrics 18 用例通过；实际本机采样的两次耗时 7ms / 6ms，发现 2 GPU 与 4 WebKit content 候选且正确标注归属不明。数字是测试 collector 的测量，不是旧客户端 CPU 改善幅度。
- 前端类型检查与构建通过；既有大 chunk 警告保留。Clippy 通过，有既有警告。无独立前端 lint 脚本，未引入新工具。
- 真实浏览器：桌面诊断弹窗布局、可选 JSON、后台剪贴板拒绝提示已验证；工具组 120/500 的挂载、追加、跨页搜索已验证。窄屏诊断截图测试被浏览器安全策略阻断，未绕过，不声称窄屏实测通过。
- 本版仅在内存保留，应用重启后清空；界面卡顿恢复后可复制，强制结束/重启前未导出的记录无法恢复。日志不自动上传，不能替代原生调用栈。
- 尚未复现原始百文件任务的整机满载现场；长思考稳定前缀分块、单个大 Markdown/payload 的更深优化暂未实施，避免无测量改写造成内容完整性回归。
- 本轮不替换或重启正在运行的安装版，不提交、不推送；新功能需运行本次代码构建的客户端。

- 原生 metrics：27 项通过，覆盖默认开启、偏好持久化、损坏偏好安全关闭、保存失败、线程停止/重启、首次 CPU 基线与 5 分钟/60 条限制。Clippy 通过，存在警告。
- 前端构建通过，保留既有大 chunk 警告；最后异步反馈保护改动后类型检查及全量测试通过。git diff HEAD --check 通过。
- 本次新摘要/导出/开关通过组件和模块测试；浏览器诊断目标此前受安全策略限制，未绕过，也不把此前旧版弹窗验证算作新交互验证。真实原生保存对话框、重启后的 UI 状态与多端广播尚未端到端实测；原生偏好重载与广播调用链已分别测试/核对。

- 默认日志仍仅在内存；开关偏好落盘并不意味着日志持久化，关闭会清空未导出的记录。完整导出文件只在用户操作后生成；不会自动上传。
