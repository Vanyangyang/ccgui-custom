# CCGUI 内置助手提醒与独立旁白

完成提醒和独立旁白由 CCGUI 自己的原生服务、持久化存储和透明窗口管理。聊天内的 Intelligence UI 继续作为交互主入口。实现复用 CCGUI 已有的事件发件队列、会话导航与草稿反馈；没有引入外部 Spellcast 源码、样式、字体或运行时依赖。

独立 Spellcast 接入已退役：设置不再提供工作台、连接开关、重连或安装授权，原生与 Web 不再暴露旧查询、写入或宿主命令，也不再探测外部服务。旧 `spellcast-canvas-bridge` 回发插件会持久停用，不能重新启用或安装。应用不会删除原插件文件、登记和历史 KV，也不会自动清理它们；用户手动删除这些数据后，重新安装或启用仍被拒绝，旧检查点照常作为数据保留。内置提醒、旁白和聊天交互回答不需要 Spellcast skill、MCP 或插件。外部 Spellcast 的项目、Canvas 和法阵工作台未被迁入 CCGUI，不以删除连接入口冒充这些能力已内置。

## 入口与默认行为

- 设置 → 系统 → 助手与旁白：独立原生页统一管理功能开关、作用范围、旁白生成来源、完成播报、显示器和阅读字号。新配置总开关默认开启，主动旁白默认关闭；一次性导入时保留用户原来的显式选择。暂停旁白会取消待发生成并收起可见旁白，完成记录与独立播报开关继续保留。专注模式只在真正查看聊天时静默旁白；设置页、其他中心面、过期页面关注状态不算正在查看聊天。
- 顶栏铃铛：查看未读完成和最近最多 10 条旁白，包括已经过期或忽略的旁白。总开关关闭时仍能显式查看历史和重新启用，但不显示未读徽标。
- 聊天内：前台来源会话的旁白显示在输入框上方。分屏仅当前聚焦的会话展示；卡片头部左侧展示来源引擎图标与单行截断的会话名称（优先手动标题、其次自动/首句会话标题，缺省回退短会话 ID），右侧注明生成该旁白的模型与推理强度（如 `Gemini 4 Argon · medium`）；展开、固定、忽略和带入来源草稿均为明确操作。
- 桌面浮层：不主动抢焦点。只展开最新一条完成提醒，其余完成按每页 10 条展开；旁白最多两条。未读完成不因时间而消失。未固定旁白约 18 秒后收起，悬停、键盘焦点和拖动暂停计时，拖动结束有阅读宽限。过期记录可以从铃铛找回。
- 原生桌面主窗口提供这些入口；Web、开发配置和辅助浮层不能启动主应用的聊天存储、插件或热更新接管链。浮层独立启动仍遵守首个 React 提交后的启动看门狗确认。

## 事件、确认与存储

普通本地会话的运行事件先进入有界 SQLite 发件队列。只有成功预留持久化容量后，才给 CLI 设置专用完成通知归属标记。自定义 CLI home 和项目 hooks 不再阻止内置捕获；Sidechat、BTW、工具受限辅助调用、托管子任务、远程及非 GUI 来源仍不参与。来源范围跟随 CCGUI 的已启用引擎和会话本身的供应商，覆盖 `config::ENGINES` 中的全部十二种引擎，不另设一份容易漂移的开关。禁用来源不丢弃已经接管的完成记录；旁白请求和晚到结果另行核对来源仍启用。

已获得接管资格的完成事件必须先落入通知存储，再确认出队。旁白策略版本与完成事件生命周期分离；切换旁白、暂停、专注或总开关不会让已经捕获的完成事件永久留在旧代队列。总关会停止新的接管和展示，已持久化的未读记录保留到重新启用或显式处理。重复完成不再次触发模型，旧确认不能清除新一轮结果。

完成提醒不调用模型，包含来源引擎、稳定会话/轮次、时间及有界的最后助手段落。错误、中断和回收不伪装成正常完成。来源身份包含精确工作区路径，标题不是身份键。

回到会话与带入草稿必须经过当前页面文档、精确来源、真实窗口聚焦与可见聊天状态确认。跳转失败保留提醒供重试；历史旁白允许显式回看或带入草稿，不会因此重新弹出桌面气泡。参数或旁白反馈只追加到来源草稿，不覆盖已有文本、不自动发送。定时心跳本身不清未读。

本地通知与配置存于应用目录的 `assistant-notices.sqlite`、`assistant-notices.json`；拖拽位置存于 `assistant-notices-window.json`。通知存储有容量上限，优先清理已读历史，不静默驱逐未读完成。原生窗口销毁、主窗退出、页面替换和过期悬停租约都有清理路径。

完成发件队列继续使用已有的 `spellcast-completions.sqlite` 文件，CLI 完成归属标记保留既有名称，避免模块迁移丢失待处理记录或让旧 hooks 重复通知；这些名字不提供外部连接、授权或兼容 API。旧连接开关及其代次键在设置读取和写入时丢弃，不再传到前端或重新保存。

## 原生配置与一次性偏好导入

设置保存携带原配置修订号。冲突时保留尚未提交的选择，允许明确重载后再修改；失败不报成功。总开关、暂停、供应商和模型等策略变更会撤销旧候选，不能让此前模型结果在新设置下发布。

仅在尚无 `assistant-notices.json` 时尝试一次性导入旧偏好：只读投影原状态库的 `observer_enabled/observer_provider/paused`，以及完成库中的 `voice_enabled/display_target`。成功后写入完整原生配置，以后不再访问旧库；已有原生配置优先。导入不启动外部服务、hooks 或模型，不修改旧库，也不读取或迁移画板、草稿、记忆和完成正文。原旁白来源映射到 CCGUI 当前供应商及其默认模型/强度，不导入旧 runner 中的固定模型或代理。导入失败明确显示，用户仍可保存一份新的原生配置恢复。

原来的三种阅读字号保留为原生卡片设置：正文 80–300%，标题与界面 80–200%，均以 10% 为步长，默认 100%。原 WebView localStorage 的字号没有可信跨应用读取入口，不宣称已自动导入。字号实际作用于桌面浮层、同源内联旁白和铃铛历史卡片。主题、语言和字体跟随 CCGUI 通用设置；原独立应用的开机启动项属于其进程生命周期，不迁入助手配置。

桌面显示器可跟随前台窗口所在屏幕，或固定选择显示器。固定屏断开时临时回退活动屏，保留选择供重连恢复；跨屏重新夹紧位置，同屏保留拖动位置。设置本身不会打开浮层或抢焦点。

Windows 完成播报为本地合成提示音和一句固定离线语音，不调用模型、不朗读任务内容。保留原开关（默认开启）、25% 音量、3 秒合并、逐引擎 90 秒冷却与当地 22:00–08:00 静音规则；这些固定策略不伪装成可调设置。只处理应用本次启动后的新完成，关闭时清空待播并取消播放，不补播静音期间的内容。非 Windows 明确标示语音不可用。

## 旁白生成与供应商

功能作用范围与旁白生成来源分别展示。旁白默认仍为 Vertex `gemini-4-argon` / `MEDIUM`；用户也可选择已启用 Claude、Codex、Pi 的可用模型和推理强度，使用对应引擎在 CCGUI 当前选中的供应商。其它引擎照常提供完成及观察来源，但不将尚无隔离适配器的引擎冒充成生成选项。保存选项暂不可用时保留选择并明确显示，不换用另一供应商。Claude/Codex/Pi 复用无工具的独立结构化调用，不载入项目技能、hooks 或主会话历史；Vertex 继续使用固定直接请求。配置探测不调用模型；旁白失败不影响完成提醒与历史。

普通本地回合运行中已接入稳定边界进度观察：非流式整段助手消息，或助手文本转入 tool / thinking 的边界，可形成检查点；逐 token 增量和 patch 快照本身不触发观察。去掉首尾空白后的候选至少包含 80 个 Unicode 字符，进度摘要最多 1,500 字符、目标最多 500 字符。同一回合的检查点写入尝试至少间隔 30 秒，写入失败或没有可用观察租约也消耗该间隔；不会为了补发旧片段逐 token 重试。成功完成后的观察检查点仍保留。

运行中与完成后的观察共用同一来源的 120 秒模型尝试冷却、内容与检查点去重，以及全局最多两条的「活跃旁白 + 待生成候选」预算。进度检查点和策略候选均有 180 秒有效期；旧完成仍入库，但过期候选不因启动或导入配置而补生成旁白。这些是触发上限，不承诺每隔固定时间产生旁白。模型仅接收有界目标、最新变化和短事实，不发送整段会话历史；单次请求最多 60 秒。返回空观察是正常结果，网络失败不会冒充成功气泡。

取消、回合结束或同一来源开始新 turn 会使旧进度检查点失效；消费和结果发布还要重新核对来源、开始时间、归属预留及当前策略 epoch。关闭/暂停旁白、专注模式实际生效变化、语言或可用性变化会撤销旧候选；恢复后使用新 epoch，不能把恢复前的晚到结果重新发布。这里隔离的是尚未发布的旧结果，不把已展示旁白的过期、固定或显式忽略规则改成新回合自动删除。

可选进度存储与完成通知的持久化、入库确认分开处理：进度表或观察租约读写失败只降级旁白可用性，不阻断已接管完成的入库和确认；完成提醒仍不调用模型。通知主库或完成队列自身故障仍如实报告，不能据此声称整个 SQLite 文件故障也已隔离。实现边界见 `src-tauri/src/assistant_notices/observer_progress.rs`、`src-tauri/src/assistant_notices/completion_outbox.rs`、`src-tauri/src/assistant_notices/policy.rs` 与 `src-tauri/src/assistant_notices.rs`。

通知数据、模型摘要与用户对话不写入诊断日志。这里的摘要限制不等同于通用敏感数据识别器，用户应按实际工作内容决定是否开启主动旁白。

## Intelligence UI 与截图附件

交互回答参数按会话、消息、代码块及源码哈希保存；失败保留输入，修订号冲突不会覆盖其它端。重试先核对存储：原版本未变才重试原写入，已提交且参数一致则恢复成功状态。用户可明确重新加载已保存参数。参数反馈只追加到来源草稿，见 [交互式回答](./interactive-answer.zh-CN.md)。

Sidechat 支持截图粘贴、预览、移除及纯图片发送；附件按父会话隔离，发送失败保留。主输入框带图片的 `/btw`、`/sidechat` 仍走相应旁聊链路，继续使用原来的权限限制。

`live_fixed_vertex_observer_smoke` 是忽略的显式联网测试，只用合成上下文执行一次固定模型请求。普通测试不会调用真实模型或打开生产队列。组件、模拟 IPC 和纯原生状态测试不等同于真实透明窗口验收；首次绘制、跨 DPI 拖拽、点击穿透、主窗退出和安装版来源回跳必须另行记录实际结果。
