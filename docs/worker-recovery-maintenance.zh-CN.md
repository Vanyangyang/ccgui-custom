# 已完成协调 worker 的维护恢复

普通重启可能丢失根协调会话的内存能力，但独立 worker 继续执行并保存完成事件。旧宿主若已将该路由标记为 `worker-coordinator-fault`，不会重启观察器；这也可能阻塞包含恢复修复的自更新。

`ccgui-next.exe --worker-recovery` 是范围受限的原生维护入口。从标准输入读取一个 JSON 对象，输出不含凭据及对话正文的 JSON 核验报告。它不启动第二个桌面、不迁移或写入数据库、不恢复协调能力、不修改自更新事务，也不重发输入。

先使用 `action: "inspect"`，明确指定 `workerId`、`runId`、`engine`、`sessionId`、`workspacePath`。只有只读任务账本确认该会话是拥有子任务的根协调者，原 worker 的 PID、启动时间和可执行文件身份有效，身份完全匹配，原生进程及读取器均已结束，事件与回执存储无故障，且完整持久化日志具有唯一终态，才返回 `head`、`terminal` 和 `archived`。

维护人员核对主流程已保存原输出后，可提交相同身份及 `action: "retire"`，附上刚才的 `expectedHead` 和 `expectedTerminal`。入口再次执行全部核验，调用原 worker 的 `Retire` 命令，由 worker 自己持久化最终回执并归档。稳定命令 ID 由 worker ID 和 head 派生；回执不确定时只能重复同一请求核对原归档，不能重派任务。只有重新打开并严格核验归档成功后，才报告 `archived: true`。未完成、日志有缺口、身份变化、终态不唯一、无原进程且无正式归档等情况均拒绝恢复。

归档是运行结束的证据，不是原输入已送达的证据；原 `unknown` 回执须继续保留。工作台保存旧结果后，仍仅接受用户新的明确输入，不能自动重试原输入。

此入口不清除旧桌面的内存故障，也不退出桌面。若旧版本缺少在线恢复入口，需要在确认其他工作结束、保存窗口草稿并获得维护重启授权后，通过应用自身的重启入口重启旧桌面。已经准备好的自更新仍由原生协调器按正常检查点流程执行；不得杀进程、覆盖运行中的 EXE、编辑数据库或自更新状态来绕过交接。归档前不能用普通退出关闭仍持有完成日志的 worker。
