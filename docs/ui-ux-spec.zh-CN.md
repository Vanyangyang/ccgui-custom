## 1. 维护约定

- **谁改谁更新**：新增或修改用户可见的交互反馈、基础组件视觉、动效时长时，在同一个提交里更新本文对应章节。
- **新增刷新/重载入口必须登记**到 [§7 刷新入口清单](#7-刷新入口清单)；没登记的算没做完。
- **规则要能落到代码**：每条规则写清文件和常量名。文档与代码冲突时**以代码为准**，并立即修正文档（或反过来改代码 + 补充说明）。
- 只维护这一份中文文档，不再派生第二份双语副本，避免两边漂移。
- 规则来自真实问题，不预先发明：同一条规则第二次被违反时，才值得写进来。

## 2. 设计基础

### 2.1 Token 优先

- 颜色、圆角、阴影、动效一律引用 `src/styles/theme.css` 的**语义 token**（`text-*`、`background-*`、`border-*`、`foreground-icon-*`、`notification-*`、`shadow-*`），不写死色值、不直接引用 `slate-*` 之类的原始色阶。
- 文本排版用 `src/styles/typography.css` 的 `text-*` 系列（`text-body-medium`、`text-caption-1-regular`…）。`cx()` 依赖 `src/utils/cx.ts` 里登记过的文本族，新增文本族必须同步登记，否则会被 tailwind-merge 当成颜色丢掉。
- 关键帧动画定义在 `src/styles/theme.css` 的 `@theme` 里（如 `--animate-refresh-spin`）并配 `@keyframes`，组件只引用动画名。

### 2.2 组件优先

- 交互控件优先复用 `src/components/base/*`（`Button`、`IconButton`、`Dropdown`、`Select`、`Input`、`Switch`、`Tooltip`…）。页面内自造按钮要么说明 base 组件为什么不适用，要么把它沉淀成 base 组件。
- 尺寸以组件自身定义为准，不在调用点临时改高度：`Button` medium 36 / small 32 / xs 24，`IconButton` medium 36 / small 32。
- `Button` / `IconButton` 需要承载动态图标时用 `children` 覆盖默认图标（两者同一契约），不要用 `[&_svg]:animate-spin` 这类穿透选择器改图标行为。
- 应用跑在 React 18：base 组件 props 里声明的 `ref`（`Input`、`Button` 等按 React 19 写法声明）在函数组件上会被 React 丢掉，传了也拿不到 DOM。要操作 `Input` 的输入框（初始聚焦、全选）就给 `groupRef` 再 `querySelector("input")`（`PromptDialog`、`RenameSessionDialog` 都这样做；此前 `PromptDialog` 的「打开即聚焦并全选」因此从未生效）。
- 图标一律取 `lucide-react/dist/esm/icons/*`（按需具名导入）；不新引图标库，也不自绘 SVG。同一入口出现在多个位置时三处共用同一个图标：插件/插件市场 = `layout-grid`（侧边栏 `sidebar-chrome.tsx`、插件中心页签 `use-chat-tabs.ts`、设置页插件条目无品牌素材时的兜底 `PluginSettingsNavIcon.tsx`）。

### 2.3 文案与无障碍

- 用户可见文案一律从 `src/i18n/zh.ts`、`src/i18n/en.ts` 取，两个语言文件同步新增 key，组件里不写死中文。
- 图标按钮必须同时有 `aria-label`（可访问名）和 `title`（指针悬停）。可访问名用**动作名**（"刷新"、"重新加载"），不用"点这里"。
- 需要解释性文案、快捷键或多行说明时才用 `Tooltip`（`src/components/base/tooltip/tooltip.tsx`）：它基于 react-aria，trigger 必须是 react-aria 组件或包在 `Focusable` 里的元素；触屏上不可达，所以**关键信息不能只放在 tooltip 里**。

### 2.4 展开 / 收起动效

- **把下面内容推开的展开/收起一律做高度过渡，不允许条件渲染直接闪现**（`{open && …}` 少了过渡就是瞬间抽走 / 塞回）。实现统一用 CSS `grid-template-rows: 1fr ⇄ 0fr`，让浏览器插值轨道高度、兄弟行被平滑推开；不用 `max-height` 猜高度，也不用 JS 逐帧量高。现成实现两处，不要另起：侧栏树/列表用 `src/components/application/ai-chat/repo-tree.tsx` 的 `SidebarDisclosure`（`WorktreeGroup` 分组与线程列表共用：`300ms` + `ease-in-out` + `motion-reduce:transition-none`）；消息/面板级折叠用 `src/components/application/collapsible/collapsible.tsx` 的 `Collapsible`（额外 `opacity` + `visibility` 收尾，时长由调用点给）。两者都只转箭头方向（`transition-transform duration-150` + 展开时 `rotate-90`）并同步 `aria-expanded`。
- **收起过程中内容保持挂载，动画结束才卸载**：内容要在关闭动画期间留在 DOM 里（`SIDEBAR_COLLAPSE_MS` = 300ms 后卸载，顺带回收分页等组件内状态，下次展开回到第一页），否则收起读起来是「啪」地消失。
- **不用 `opacity` 淡出列表行**：列表淡出会在下方内容上留一帧合成残影（`repo-tree.tsx` 的注释记录了这次事故）；只裁切高度。收起期间给区域 `aria-hidden="true"` + `inert`，键盘与读屏不进入被裁掉的内容。长消息的「展开全文」（`CollapsibleMessage`，`max-height` + 渐变遮罩）是把气泡裁短而不是推动兄弟行，属于另一类视觉，不在这条规则内。
- **回归**：`tests/browser/sidebar-collapse.html` 逐帧采样「WORKTREES」分组与 worktree 子行的展开/收起高度——每个方向必须经过 ≥3 个中间帧、收起期间行仍在 DOM（只有首尾两个值＝直接跳变）；`ai-chat-sidebar.test.tsx` 覆盖收起后 300ms 才卸载。

## 3. 状态与可用性

- **AGY 禁用额度窗口**：原生 `/usage` 返回 `disabled:true` 的窗口可缺少重置时间；该窗口的剩余比例不代表可用额度，应跳过，不使其他有效窗口失效。有效的真实 0% 继续保留。所有窗口都不可用时显示不可用，不能用历史比例伪装当前额度；未禁用窗口仍严格校验数值与重置时间。

- **轻量旁聊**：仅 Claude、Codex、AGY、Cursor 提供 `/btw <问题>` 与 `/sidechat <问题>`，输入栏也可打开旁聊面板。主任务进行中仍可旁聊；旁聊有独立草稿、输出、停止和错误反馈，不改写主对话正文。`/btw` 是一次性提问，`/sidechat` 可追问或显式提升为独立对话；旁聊运行中仍可直接回车或点击「发送」提交追问（自动中断上一轮旁聊并收敛已输出内容，无需先手动点击「停止」）。复制与插回主输入框是用户操作，后者不自动发送。关闭与清理仅操作归属于同一引擎、工作区和父会话的旁聊；取消、失败和晚到事件不得清除主会话或另一轮草稿。分叉可争取缓存复用但不保证命中率；只读工具限制优先于保留完整工具前缀。
- **旁聊权限切换**：Sidechat 标题下提供「只读 / 可执行」分段双按钮（共享 `bg-background-secondary-default` 底槽），默认只读；选中态同时提供文字、`aria-pressed` 与实心品牌主色高亮（`variant="primary"`，`bg-button-primary text-text-white`），未选中项为透明底弱化文字（`bg-transparent text-text-tertiary`），不使用带浅蓝底色的 `ghost` 变体充当未选中态以免视觉反置。模式按父会话隔离，收起重开、重新开始和会话身份迁移保留选择，不新增独立权限配置；运行中禁用切换并说明结束或停止后可切换。可执行每轮读取父对话当前有效权限（含引擎兼容回退），沿用其原有权限映射，不自动提升为绕过审批；父权限不可读取时保留草稿并报错。切回只读后下一轮恢复引擎只读限制，继续保留旁聊历史。`/sidechat` 命令沿用该会话选择，`/btw` 始终只读。旁聊仍使用独立输出、停止与错误反馈；需要人工审批或问答时沿用交互等待提示，不代为批准。回归：`launch.test.ts`、`store.test.ts`、`SidechatPanel.test.tsx` 与原生 Sidechat 权限测试。
- **旁聊调宽**：`SidechatPanel` 的桌面左边界提供全高 8px 拖动手柄，可向左右调宽；手柄可聚焦，左/右方向键每次增/减 16px，Home/End 调到当前最小/最大宽度。`use-sidechat-resize.ts` 默认 416px、常规范围 280–720px，偏好保存在 `ccgui-next.sidechatWidth`；主会话尽可能保留至少 280px，容器不足 560px 时旁聊最多占一半，扩大后恢复偏好宽度。取消、失焦、关闭、切换会话或卸载时终止拖动并撤销未提交宽度，回收事件与帧回调；拖动只更新面板 DOM，不逐次重渲染消息树。小于 768px 仍上下排列、旁聊全宽半高并隐藏水平手柄。悬停与键盘聚焦显示分隔线，不增加尺寸过渡。回归：`use-sidechat-resize.test.tsx` 与 `tests/browser/sidechat.html`。
- **底栏布局与未知数据**：吞吐只显示有有效样本的会话、本轮或 Claude 观测速率，全无数据时隐藏入口，不展示速度「—」。上下文入口带文字与已知容量，未知占用不画假进度；已确认的模型目录容量可用于显示容量但不当作实时占用。Claude 与 Codex 订阅额度摘要和详情面板的 5 小时、7 天窗口统一按**剩余额度**展示（`100 - usedPercentage`，「用多少少多少」的递减进度条，剩余 > 25% 为蓝色、剩余 ≤ 25% 为琥珀色、剩余 ≤ 10% 为红色），避免同一卡片内混用「已用」与「剩余」。AGY 额度摘要仅显示剩余比例，重置时间保留详情与无障碍说明。窄屏允许控件组换行，完整保留工作区、分支和上下文入口。
- **对话拖放文件**：有活动会话时，把操作系统文件拖到当前对话栏（消息区或输入区，`data-conversation-file-drop`）即可加入。图片走附件，其他文件在输入框光标处插入 `@` 引用；没有活动会话时忽略，不写入草稿。松开前在整列上显示虚线提示（`chat.dropFilesHint`）。桌面端必须订阅 webview 的 `tauri://drag-*`（`getCurrentWebview().onDragDropEvent`）；订在 Window 上收不到事件。旁聊栏和侧栏不是这次落点。网页桥没有本地路径，只接收图片文件。回归：`use-composer-file-drop.desktop.test.tsx`、`use-composer-file-drop.test.tsx`。
- **每轮小结**：结束后在最后一段 assistant 回答下常驻紧凑小结，展示实际可得的总耗时、输入/输出 token、缓存命中、思考 token、工具次数和明确标为均速的整轮输出速率。发送下一轮及生成期间，已结束回合的小结、复制与元信息保持可见；仅当前运行回合的最终页脚等待结束后显示，运行中追加的引导消息不另起一轮。整轮耗时包含工具与等待；不改正文与复制结果。缺失字段隐藏，历史只提供部分用量时标为「已上报」，不推算缓存比或均速。引导消息与权限卡不分割正在运行的一轮，历史列表未变行保持引用稳定。历史原生文件没有可靠时长或计数时不补造数据。
- **Gemini 4 API 容量**：挂载的精确 API ID `gemini-4-argon` 在没有原生报告、会话记忆或目录容量时，可展示官方公布的 1,048,576-token 输入/输出共享容量；带档位后缀的 AGY 订阅别名不据此推断。原生报告始终优先，该值不代表 CLI 当前占用或自动压缩阈值。[官方模型说明](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/start/get-started-with-gemini-4)，2026-10-16 核对。

- **交互式回答（Intelligence UI）**：没有专用指令，由模型按问题自行决定是否生成；`/ui` 应用指令已移除，输入 `/ui …` 按普通文字或用户自定义命令发送。`Markdown.tsx` 仅对 Codex 与 Claude assistant（`supportsInteractiveAnswer`）的完整 `ccgui-ui` 围栏挂载 `InteractiveAnswer`；生成中显示状态，失败保留文字与「查看原文」。原文默认折叠，展开沿用 200ms `Collapsible`；「重置参数」恢复模型初值并保存，不调用模型。组件使用语义颜色和容器自适应布局，480px 以下单列，表格仅内部横滚，减少动效偏好停止组件过渡。参数按真实会话/消息/代码块与源码哈希保存，刷新/重启恢复；读取完成前禁用控件，保存错误保留输入，冲突不覆盖新版本。「使用这些参数继续讨论」仅向来源会话草稿追加可见参数与来源标识，不自动发送；无稳定来源明确说明仅本页保存并禁用反馈。Intelligence UI 为主入口，不自动发布到 Canvas。回归：`interactive-answer`、`use-composer-interactive.test.tsx` 与 `tests/browser/interactive-answer.html`。细节见 [GPT 交互式回答试用](./interactive-answer.zh-CN.md)。

- **聊天图片与主动交互**：普通本地 Codex 与 Claude 对话的宿主上下文提供简短 Intelligence UI 说明（Codex 为开发者指令，Claude 为追加系统提示），适合参数比较与计算探索时主动使用；不替换用户配置或原有角色指令，不要求每条回复生成控件。生成图片独立显示为助手附件，沿用缩略图、点击放大、滚轮缩放/拖动与 Escape 关闭；Markdown 本地/工作区相对图片使用同一组件。缩略图受容器宽度限制，读取失败显示文件名，远程或不支持来源显示占位，不放宽 CSP、不自动代理下载。图片切源和卸载丢弃晚到读取结果，内嵌载荷不作为加载占位文字显示；历史恢复沿用同一渲染路径。Codex 原生出图与已识别的 MCP/动态工具图片在助手独立行展示，工具详情保留原文字并省略图片二进制。内嵌结果限制每张 8 MiB、每次调用最多 16 张/32 MiB，格式或预算不符在工具详情保留省略原因；不把失败结果显示为成功图片。同调用的双份历史合并去重，失败优先；原生记录同时保留路径和有效内嵌结果时优先内嵌图，仅有文件路径的记录仍依赖原文件存在。

- **图片批注**：会话内的图片预览（输入框附件、聊天图片与 Markdown 本地图片）工具栏提供「批注图片」切换；会话外预览（如文件页）不显示。批注模式下左键拖动画矩形（小于图片 1% 的拖动视为点击），按住空格或中键拖动平移，滚轮缩放照常；框坐标按图片比例保存，放大、平移后仍与图片对齐。最多 9 个框，每条批注最多 500 字，所有框都有批注后才能「添加到草稿」。批注模式下点背景或图片不关闭；Escape 先退出批注输入框，有批注时再确认放弃，× 在有批注时同样先确认。添加时在原图副本上画红色编号框并导出 PNG，经该会话输入框的附件管道加入（聊天图片同时附原图，输入框附件只追加标注图），并向同一会话草稿末尾追加「[图片批注]」文字块（逐条列出百分比范围与批注），不覆盖草稿、不自动发送；引擎不支持图片时只追加文字并注明。渲染或附件失败时保留批注并显示错误，不改动草稿。实现：`src/components/base/image-annotation/`、`image-annotation-target.tsx`；回归：`image-lightbox.test.tsx`、`geometry.test.ts`、`image-annotation-target.test.ts` 与 `tests/browser/image-annotation.html`。

- **旁聊截图附件**：Sidechat 输入区复用主输入框的图片粘贴、预览、移除和保存错误反馈，可只发送图片；附件按父会话隔离，关闭重开保留。保存中禁用发送，发送失败保留正文和图片，接受后只清除本次附件。主输入框 `/btw`、`/sidechat` 带图时仍按旁聊命令路由，保留自定义命令优先级和原有只读边界。
- **旁聊运行反馈**：`SidechatPanel` 与 `/btw` 共用 `SideRunStatus`，复用主对话的 `AgentThinking` 波点、计时与静态等待样式；整个运行期间保留状态行，包括回答正文已经开始输出时。阶段只来自真实引擎事件：发起请求、等待模型、思考、工具执行、输出、重试、整理上下文、后台等待及交互等待；工具名称与重试等详情保留实际返回内容。显示从本轮发起时计算的总耗时，以及距最近一次有效事件的秒数；尚未收到事件时明确说明。连续 60 秒没有新事件时停止状态动画、提示「暂无新活动」并说明高思考强度或整步返回的模型在推理完成前不会推送中间输出，提示可继续等待或停止后重试，不以计时或动画证明任务存活，不自动超时、重发或判定失败。新事件解除静默提示；收起重开不重置计时。`turn_complete` 仅回到等待，不结束整个运行；终态与停止沿用原生命周期。旁聊收到尚不支持处理的提问或审批时，明确显示交互等待和停止后在主对话继续的提示，不显示无效的批准按钮。进度与正文合并为单次 store 更新，重复、乱序、其他运行及终态后的事件不刷新活动时间；计时只更新状态组件，卸载时清理。回归：`progress.test.ts`、`store.test.ts`、`SideRunStatus.test.tsx`、`SidechatPanel.test.tsx`；浏览器 fixture 提供 waiting / quiet / tool / retrying / streaming 与新活动、完成模拟入口。

- **Claude 原生后台任务**：输入框上方 `RunStatusStrip` 的「任务」胶囊采用原生 `tasks` 事件完整目录，列出任务名称、后台命令 / 子代理或原生类型、运行中 / 暂停 / 已完成 / 失败 / 已停止 / 未知状态；暂停不算成功，ambient 观察任务保留可见但不计入运行中数量或活动 / 静默回收保护；胶囊直接显示运行中数量与已完成 / 总数，点击行查看摘要和进度。行首状态标记（`RunStatusStrip.tsx` 的 `TaskStatusGlyph`）：运行中为蓝色呼吸点，已完成为静态绿点，失败 `!`（红）、已停止 `■`、未知 `?`、暂停 `Ⅱ`；运行中的 ambient 观察任务显示中性、静止的空心圆环，不呼吸也不冒充已完成的绿点。类型标签只来自本地化词表（后台命令 / 子代理 / 工作流 / 监控 / 队友 / 云端会话 / MCP 任务），默认的 `task` 与尚未映射的类型统一显示「原生任务」，绝不展示原始协议标识；任务详情的返回按钮为「返回任务列表」，待办清单详情为「返回待办清单」。存在原生目录时不再重复展示工具行推断出的 Agent，原有待办项的胶囊改标「待办清单」以区分；其他引擎和缺少原生数据的旧历史保留「子代理」展示。首条回复的 `turn_complete` 只收敛该回复的文本、思考与用量，不释放运行状态；排队消息也不由它直接发出，而是按下文在随后的「空闲等待」边界发出；尾部等待标签随原生活动变化：后台等待（`waiting`）显示「等待后台任务」，Claude 处于 `requires_action`（等待权限或提问回答）时显示「等待你操作」（`MessageTimeline.tsx`，i18n `chat.nativeWaiting` / `chat.nativeRequiresAction`），其余仍是通用思考标签；最终 `done` 才结束忙碌。后台等待期间运行仍算忙碌（`turn_complete` 不清除 `streaming`），但在输入框发送消息的去向与原生 CLI 一致，按 CLI 当时的状态分三种：
  - **主回复已结束、后台任务仍在（`nativeActivity` 为 `waiting`；此时主线程空闲，而后台子代理仍在做模型调用 / 读文件时 CLI 自身会一直报「运行中」、直到全部结束才报空闲，这不影响判定——引擎只把追问、通知触发的续答和主线程自己的流式内容算作「回复中」，子代理的权限提示与运行状态翻转不改变活动），且满足下文「存活通道条件」**：输入框发送的消息（`use-composer-actions.ts` 的 `submit` → `sendWhileBusy`）立即处理，不再排到后台任务之后，也排在队列里已有的行之前。它作为用户消息（与启动时的消息同一格式，含图片与已选 agent 的指令块）写入仍存活的 CLI 标准输入（IPC `send_follow_up`，不新建进程、不打断后台任务）：写入前输入框先出现用户行，活动记为运行中、本轮计时重新开始，并解除 Stop 留下的停靠；这条回复结束后回到「等待后台任务」，没有后台任务时才有最终 `done`。发出前状态已变（等待内置 agent 解析期间 CLI 离开了空闲）时，消息交还原来的去向：来自队列的回到队首，输入框的消息排到队尾，会话已空闲则按普通发送。失败回退（`deliverFollowUp`）：宿主答复没有可接收的存活运行（`Ok(false)`：运行刚结束、标准输入已关闭、非 Claude 引擎）时撤销乐观更新（用户行、活动、计时、错误），再按当时状态处理——用户在此期间按了停止、队列已经停靠，文本回到停靠队列的队首，不重启刚停止的运行；会话已被下一次运行占用（上一个运行的最终 `done` 已触发排空并启动了新运行），文本回到队首、随那次运行的最终 `done` 发出，不并发起第二个进程；其余情形（运行还没收到最终 `done`，或已结束）按普通发送新建进程。写入失败（`Err`：图片读取、管道写入）同样撤销乐观更新并显示错误横幅，文本回到队首并标记 `noLive`：不在每个空闲边界重试，到该运行的最终 `done` / `error` 才按普通发送发出；若该运行恰在此时已结束、会话空闲且没有停靠，则立即按普通发送发出。
  - **回复生成中（`running`）**：消息进入该会话的排队队列（`use-composer-actions.ts` 的 `submit` → `sendWhileBusy` 排入队尾；原生同样排队）；回复结束、CLI 下一次进入空闲等待（`waiting`）时，队首经上面的存活通道发出，队列按先进先出、每个空闲边界只放出一条，不越过队首：队首已标记 `noLive` 或不满足存活通道条件时，整个队列继续等到最终 `done`。一次响应结束会连续产生两次 `waiting` 活动：放出一条后的 10 秒「放行保护」（`followUpAt`）使第二次 `waiting` 既不会放出第二条，也不会把乐观的「运行中」改回等待；CLI 自己的下一次 `running` / `requires_action` 活动或响应结束事件提前解除保护，CLI 一直没有反应时保护在 10 秒后自行过期（没有定时器），其后的下一次 `waiting` 才放行下一条。Stop 留下的停靠（见下）同样阻止放出。
  - **不满足「存活通道条件」时排队**：条件在发送时检查，并在每个空闲边界对队首重新检查——暂时性的不满足（回复生成中、`requires_action` 等你操作、尚有待处理的卡片）在之后的空闲边界满足条件时即走存活通道；持久性的不满足（非 Claude 引擎、运行已被终止、电脑操控、没有启动记录、启动后批准过目录授权或改过启动参数）继续排队到最终 `done` 或 `error`，届时按先进先出每次发出一条（每条新建进程；新进程重新记录启动参数，其后的行可在它自己的空闲边界走存活通道）。条件由 `live-follow-up.ts` 的 `liveFollowUpBlocker` 判定，任一项不满足即排队：（1）Claude 引擎，且会话忙碌；（2）有路由到该会话的运行，且没有被用户终止；（3）CLI 处于空闲等待（`waiting`），生成回复中、`requires_action` 等你操作、尚未上报原生活动的旧版 CLI 都不算；（4）不是电脑操控：消息不是 `/ccgui-cua` 任务，运行也没有挂着电脑操控驱动；（5）没有待回答的提问、目录授权或计划审批卡（`awaiting_review` / `deferred` / `submitting`）；（6）本客户端有这次运行的启动记录（别的入口发起、本端旁观接管的运行没有，无从比较启动参数）；（7）启动后没有批准过目录授权：CLI 的 `--add-dir` 只在启动时生效，旧进程会再次拒绝同一路径，而授权是全局的，所以批准后所有已启动的存活运行都不再走存活通道，下一次启动自带授权并重新记录；拒绝或保存失败的授权不算；（8）启动后没有改过模型 / effort / Ultracode / 渠道 / 权限模式（本客户端在启动时发送这些配置，改后的值只对新进程生效）。模型与 effort 同时认选择器的写法与 CLI 自己回报的完整名称，二者互换（如 `opus` 与完整模型 id，或会话刷新与 CLI 回报交替写入）不算改动，只有选了另一个模型 / effort 才算；Ultracode、渠道与权限没有对应的 CLI 回报，直接比较。

  排队行的「发送」按钮（`sendQueuedNow`，下称「立即发送」）把该行移到队首并解除停靠：（1）会话已不忙碌：直接发出；（2）CLI 空闲、满足存活通道条件且该行没有 `noLive` 标记：立即写入存活的 CLI；（3）其余存活的 Claude 运行统一发原生 interrupt，不终止进程，不要求有后台任务，也不要求满足存活通道条件。刚启动尚未上报活动、`running`、`waiting`、`requires_action` 和电脑操控均遵循此规则；模型 / effort / 渠道 / 权限变化、启动记录未知、新目录授权和 `noLive` 只限制消息直送，不限制打断。该行在随后的空闲边界重新检查直送条件，满足则发出，否则等最终 `done` / `error` 按原规则新建运行。等待确认期间该行仍可见；5 秒内重复点击合并，之后点击重发原生打断，失败不升级为终止。除 Codex 按上文使用原生引导外，其他非 Claude 引擎保留原有终止后发送行为。后续行照常按各自边界发出。

  **停止（停止按钮、停止快捷键与电脑操控的全局 Esc，`interrupt`）遵循 Claude 原生打断**：所有存活的 Claude 状态都先停靠队列，再经 IPC `interrupt_turn` 向 CLI 标准输入写入 interrupt 控制请求，不结束进程树。已生成的部分保留；请求本身不封存回复，CLI 确认后的 `turn_complete`（`interrupted: true`）才按普通响应边界封存，请求与确认之间晚到的增量仍在同一气泡里，不显示为错误。无后台任务也走此路径；启动窗口的 `running → interrupt ACK → init → result(error_during_execution) → idle` 收敛成被打断回复和一次最终 `done`，不留下由强杀造成的空会话。后台任务的状态仍只由原生事件决定。
  - 等待与重试：请求尚未确认时，尾部持续显示「正在停止」及「尚未确认停止，5 秒后可再次点击停止重试」；迟到的 `running` / `requires_action` 不清掉待确认状态。5 秒内的重复点击合并，超过 5 秒再次点击只重发原生 interrupt；没有定时自动重试，也没有自动或重复点击升级终止。CLI 已回到空闲后 1 秒内的点击仍合并，之后点击可再次发原生请求；新的回复不受上一条回复的防抖限制。纯后台等待、已确认没有主回复时，interrupt ACK 只恢复 `waiting`，不伪造 `done` 或任务终态。
  - 启动与失败：Stop 早于进程登记、`interrupt_turn` 返回 `false` 时，保留停止意图，待同一 `send_message` 登记完成后补发一次原生打断，跟随会话 ID / 运行 ID 的迁移。首条用户消息必须先于 interrupt 写入，启动调度不能颠倒顺序。已登记运行返回 `false` 只代表没有可用的存活输入通道，按无活进程本地收尾，不调用终止 IPC。管道写入失败或 5 秒写入超时返回 `Err`，显示本地化错误、保留「正在停止」和可重试状态，绝不当作进程已退出；旧运行的晚到答复不得停止或污染新运行。
  - 电脑操控的 Claude 运行使用相同的原生打断，驱动和全局 Esc 仍按实际运行生命周期管理，只有真实最终结束才清理；不能仅因请求已写入就声称驱动已卸载。消息直送仍排除电脑操控，避免普通追问继承机器操作能力。非 Claude 引擎保留现有终止行为。本次不提供「强制结束」，也不自动恢复历史空会话。

  **单个原生任务停止**：`RunStatusStrip.tsx` 的任务详情仅对当前 Claude 原生目录中具有有效运行 ID 与任务 ID、状态为「运行中」或「暂停」的任务提供「停止此任务」按钮（base `Button`，secondary / xs）；旧历史、其他引擎和终态任务保持只读。点击无需二次确认，立即改为「正在停止…」并禁用防重，失败在同一详情以 `role="alert"` 显示原因并可用原按钮重试。请求经 `ipc.stopNativeTask` / `stop_native_task` 传目录的真实任务 ID 与 `nativeTaskRunId`，只发原生 `stop_task`，不终止整个会话或修改发送队列。只有宿主原生任务目录已确认终态（或任务已终态）才完成请求，返回实际的 `completed` / `failed` / `stopped` 与精确任务 ID；不是收到 ACK 就成功。写入、原生拒绝、断开、超时以及任务 ID 不匹配 / 非精确终态的响应均为失败。界面不乐观改标「已停止」；IPC 答复先到或 Web 断线漏掉 `tasks` 事件时，`store/native-tasks.ts` 的 `applyConfirmedNativeTaskStop` 把返回的真实终态归并到仍匹配的原会话 / 运行 / 任务，任务已完成就显示「已完成」，不覆盖目录中已到达的其他终态。归并只更新该任务并同步后台活动保护，保留其他运行中任务与等待用户操作的保护，不伪造整个运行结束；归并后解除进行中反馈。同一运行 / 任务 ID 的已确认 `completed` / `failed` / `stopped`（来自目录事件或停止结果）不被跨通道晚到的 `running` / `paused` 快照覆盖（`mergeNativeTaskSnapshot`），其他任务字段与事件序号继续更新；`unknown` 不受此保护，新运行清空旧目录后可正常运行。请求反馈保存在 strip 层，返回列表、切换详情和收起浮层保留当前任务的防重状态；会话 / 运行切换、任务删除、原生终态与卸载会隔离旧回调，晚到错误不覆盖另一任务或复活终态操作。回归：`RunStatusStrip.test.tsx`、`agent-task-steps.test.ts` 与 `native-tasks.test.ts`。

  **单任务停止后的运行收尾**：Claude 在已空闲时停止后台任务，可能只发 `killed` / `stopped` 状态，不再发送新的空闲事件或续答。`claude_lifecycle.rs` 不把停止通知当成新回复；只有此前原生已空闲、主回复不在进行中、后台任务已清空且其他自然完成任务的待续答也已收敛时，才结束这次运行。任务快照与终态补丁的先后顺序、无快照旧协议、停止通知省略均有回归；真实 CLI 验证使用隔离的 `real_native_claude_task_stop_smoke`，不操作用户的原会话。

  **停靠与恢复**：原生打断的停止把队列停靠（`queueParked`）——停靠期间空闲边界不放出行，最终 `done` / `error` 也不发出；其他引擎的终止型停止和已确认无活进程的本地收尾通过 `interrupted` 停靠。用户的任何一次显式发送都解除停靠，并对整个队列生效：CLI 已空闲且满足存活通道条件时，这条消息直接写入存活的 CLI（排在队列行之前，队列行随后每个空闲边界放出一条）；否则排到队尾，队列按先进先出在空闲边界每次放出一条，或在最终 `done` / `error` 发出。排到队尾的发送解除停靠，但不取消仍在等待的打断请求。Stop 到达时仍在解析 agent 或写入存活通道的队列行，失败或尚未写入就回队首，不能越过停靠重新启动。没有任何发送时，队列到最终 `done` / `error` 也不自动发出，只由用户手动发送。

  目录明确有运行中后台任务、或正处于 `requires_action` 等待你操作的 run 不参与 30 分钟静默孤儿回收，直到目录终态 / 活动恢复解除保护或真实 done / error / stop 清理路由，不生成假心跳。任务状态只由原生事件决定，主回复结束、停止按钮或 streaming=false 都不自动标记任务成功。终态保留至下一次运行，换会话按各自目录恢复；新 run 清空旧目录，旧 run 的晚到事件不能覆盖新任务。目录按事件序号更新并以任务 ID 去重。「未知」表示没有终态证据，出现在两处：一是宿主在没有原生终态证据时收尾——最终 `done` / `error` 或进程退出时仍为运行中 / 暂停的任务，由宿主（`reader.rs` 的 `settle_tasks`）改标「未知」，用户主动终止这次运行（其他引擎的终止型停止与终止后发送）时改标「已停止」，只打断当前回复不属于终止、任务照旧；二是没有原生目录（目录目前只保留在会话内存，如重开的标签、重新加载的历史）时，Claude 的异步 Agent 启动缺少原生终态证据，既识别结构化字段（backgroundTaskId / isAsync / async_launched），也识别历史里只剩文本的启动回执 `Async agent launched successfully`（按开头前缀匹配，同步 Agent 的汇报里引用这句话不算），不因后续回复或停止流式状态标为已完成。回归：`native-tasks.test.ts`、`native-waiting-queue.test.ts`（启动记录、空闲时直送存活进程及其失败回退、生成中排队与空闲边界单条释放、启动参数 / 别名与完整 id / 目录授权变化与待答卡回退排队、立即发送的直送 / 原生打断 / 结束后发送、各 Claude 状态的停止与原生重试、启动前停止和登记竞态、停止后的发送与停靠、被打断回复的封存与终止）、`composer-follow-up.test.tsx`（输入框的发送去向）、`chat-bridge.test.ts`（被打断回合的宿主回执）、`agent-task-steps.test.ts`、`RunStatusStrip.test.tsx`、`MessageTimeline.test.tsx`；浏览器夹具 `tests/browser/run-status-strip.tsx`（「原生 Claude 后台任务」按钮）覆盖宽窄布局。

- **桌面聊天之间的消息**：本机 Claude 原聊天通过内置 `ccgui` MCP 的 `list_chats`、`send_message`、`get_message_status` 查询和联系已保存的聊天；Claude 自带 `SendMessage` / `ListAgents` 仍只用于 agent，不作为 GUI 聊天寻址入口。发送需要用户明确授权，收到另一聊天的消息本身不构成自动回复授权。目标可以空闲或尚未打开：宿主在后台打开并加载其历史，保留模型、effort、渠道及当前用户权限，不切换当前标签、不清空当前草稿、不把后台加载当成阅读。消息正文显式标注来源聊天；忙碌、旧进程尚未退出或等待审批时排队，审批仍由用户在目标聊天处理。完整 ID 或至少 8 字符的唯一前缀才可定位；歧义、归档、远程、未知和自身目标明确拒绝。回执区分收到、排队、执行和终态；请求 ID 按发送方身份隔离，相同请求重试不能重复启动，不同正文/目标不能复用同一 ID。连接或结果不确定时不得宣称送达或自动重放。插件现有 `host:chat` 的已打开/已加载限制保持原样。

- **对话吞吐监测**：输入区状态栏显示「会话效率」「本轮效率」（tokens/s），表示主对话输出 token ÷ 同一回合耗时，包含等待、工具执行和思考；不把上下文占用或会话累计 token 当成本轮输出。详情优先展示本轮整轮效率，缺数据时显示「—」和当前采样原因；不得将整轮效率称为模型生成速度。Claude 另提供「流式输出观测速率」：同一已完成响应的原生 usage 起止计数差 ÷ 对应报告到达间隔；多响应按计数差和间隔分别求和，包含思考和工具参数输出，排除响应之间的客户端工具执行。没有对应计数、响应未完成、计数回退、服务端工具等待等响应不参加该速率，但不抹掉此前已完成响应。详情显示可测响应数 / 总响应数。该值受传输影响，不是纯解码速度；禁止按首包 1 token、文本块数或字符数推算。Codex/AGY 无可靠请求级时间配对时只显示整轮效率和一句生成速度不可测说明，不展示重复的空速率项。
- **TPS 更新与隔离**：复用现有 Claude/Codex 事件，常规遥测每个运行至多每秒一次，终态强制推送；Claude 整轮输出与时长在原生 result 到达后才可用，Codex 恢复会话缺少可信累计基线时明确无数据。无新增模型/API调用、文件轮询或逐 token UI Store 写入。未收到有效统计时不分配监测状态，保留普通工具批次的单次提交与重复消息引用稳定性。统计不修改正文、计费、工具和运行状态；发送/续轮清空本轮读数，迟到或其他 run 报告不能覆盖当前轮，停止/失败显示不完整采样。详情使用可访问 Popover/Dialog、标准焦点反馈与 150ms 动效（尊重 reduced motion），状态项可换行，详情宽度受视口约束；不新增刷新入口。
- **吞吐累计统计**：详情中的「历史整轮效率」默认折叠，展开后查看当前会话、全局及各引擎。已完成且输出 token 与耗时均有效的回合写入本机独立台账，累计效率为总输出 token ÷ 总耗时，不取各回合速率的算术平均。覆盖情况统一显示「有效样本 X / Y 回合」，Y 为有效加不参与计算的已记录终态数；说明其余回合因数据不全或未成功结束而不参与计算，不代表零速率，少量有效样本不能代表所有回合。全局可按引擎查看，当前会话按引擎与原生会话 ID 归属，无原生 ID 的草稿显示暂无会话统计。原生端统一写入、终态去重，多轮回复各自累计，切换会话或重启不重复计数。保留统计起点，旧历史没有可靠计时不补算；终态通知后重读，不随输出增量查询数据库。

异步动作必须让用户看到三件事：**正在进行**、**成功**、**失败**。失败要么有对号以外的显式反馈（错误文案 / 状态标记），要么保持原样不误导。

### 4.1 刷新 / 重新加载：转圈 → 对号

参考实现：变更面板的刷新按钮（`src/features/git/ChangesPanelHeader.tsx`），公共实现：`src/components/base/action-feedback.tsx`。

规则：

1. **进行中**：动作图标转圈，动画用 `animate-refresh-spin`（`--animate-refresh-spin`，0.6s 一圈，linear infinite）。不要用 `animate-spin` 表达刷新反馈，也不要自定第二条时长。
2. **成功**：图标交叉淡出、绿色对号淡入 —— 对号色为 `text-notification-success-foreground`，停留 **900ms** 后淡回原图标。
3. **失败**：**不出现对号**，直接复位到原图标。
4. **至少转满一圈**：动作结束时若当前这圈没转完，等它转完再换对号（图标落回正方向，不会"歪着头"顶着对号）。这就是 `spin: true` 的含义。
5. **纯视觉反馈**：反馈容器 `aria-hidden`，按钮的 `aria-label` / `title` 保持动作名不变——刷新是否有新数据由界面本身说明，不需要播报。

接入方式（按动作有没有现成的 busy 状态选）：

| 场景 | API | 说明 |
|---|---|---|
| 动作返回 Promise，点击即发起 | `useActionFeedback({ spin: true })` → `start(action, isFailure?)` | `start` 会原样返回/抛出动作结果，接回调用方既有的错误链路；非抛错型动作（把失败写进 store）用 `isFailure` 报告失败 |
| 已有 store / props 的 in-flight 标志，或动作由别处触发 | `useRunningFeedback(running)` | 标志为 true 时转圈，落回 false 时给对号 |

```tsx
// 点击驱动
const refreshAction = useActionFeedback({ spin: true });
<button
  disabled={refreshAction.feedback === "running"}
  onClick={() =>
    void refreshAction.start(() => store.refresh(force), () => store.getState().error != null)
  }
>
  <ActionFeedbackIcon icon={RefreshCw} feedback={refreshAction.feedback} spin />
</button>

// 状态驱动
const feedback = useRunningFeedback(store.loading);
<ActionFeedbackIcon icon={RefreshCw} feedback={feedback} spin />
```

补充参数：图标不是 16px 时传 `iconClassName`（`size-3` / `size-3.5` / `size-[18px]`），需要忙碌态变色时传 `runningClassName`（如用量卡片的 `text-blue-500`）。

**不要这样做**：

- 自己写 `animate-spin` / 自定义时长 / 另一种成功表达（绿字、toast、换图标颜色）。
- 把**进度**当**刷新**：插件安装、文件上传这类有明确百分比的过程用 `Loader2` 进度语言，不用转圈+对号。
- **纯文本按钮套反馈**：报错态里的文字型"刷新"（`FileTreeBody`、`EditorPane`）保持文本形态，见 [§8](#8-待收敛)。
- 成功后按钮会立刻消失的场景硬凑对号（如插件"重新加载"成功后整行转为健康态）——按规则写，但不要为了看对号拖住状态更新。
- 与刷新无关的图标（更换密钥、重置、重发）借这套反馈。它们的语义是"变更/复位"，不是"重新读取"。

例外：变更面板的 **pull / push** 只用 `ActionFeedbackIcon`（不传 `spin`），即"点击 → 对号"——云朵图标转圈读起来像故障，不像进度。这类"一次性提交型动作"允许省略转圈，但成功/失败规则同上。

### 4.2 复制到剪贴板：Copy → Check

- 用 `src/hooks/use-copied.ts` 的 `useCopied(resetMs = COPY_FEEDBACK_MS)`，成功后图标换成 `Check`，**1500ms** 后复位。性能诊断需要显式处理复制失败，使用同一 `COPY_FEEDBACK_MS` 常量，成功反馈与卸载清理语义保持一致。
- 与刷新反馈的差异：复制没有别的成功信号，所以**可访问名一起改成"已复制"**（`aria-label` / `title`），刷新反馈则不改名。这是刻意的差别，不要强行统一。
- 复制按钮旁边有明文内容时（如密钥框），保留原布局尺寸与分隔符，只换图标。

### 4.3 桌面宠物（pet overlay）

- 窗口形态：独立透明置顶窗口（`src-tauri/src/pet_overlay.rs`），无边框、不进任务栏；仅宠物图像矩形接收点击（左键拖动＝`data-tauri-drag-region`，右键循环 50%/75%/100%/125%/150% 五档缩放并立即持久化；精灵为真实按钮，键盘 Enter/Space 与右键同效，焦点环走 `focus-visible`），状态气泡与其余透明区域保持鼠标穿透，不遮挡桌面操作。
- 状态气泡（`src/index.css` `.pet-bubble`）：有活动状态时显现，显隐动效 opacity 160ms / transform 180ms（`cubic-bezier(0.23, 1, 0.32, 1)`）+ blur 消退；`prefers-reduced-motion` 下仅保留 opacity 180ms，无位移与模糊。气泡为玻璃拟态（backdrop blur + 内高光），文本两行截断（会话名 + 状态）；状态文案走 `settings.petActivity*`，`aria-live="polite"`，无活动时 `aria-hidden`。
- 位置与尺寸记忆：拖动结束保存位置、缩放即时生效并持久化；恢复位置前校验仍在已连接显示器内，落出所有屏幕则用默认位置。宠物设置（开关/角色/导入/移除/尺寸）在设置 → 其他 → 桌面宠物；移除走 `ConfirmDialog`（danger），导入失败等后端稳定错误码经 `petErrorMessage` 映射为本地化文案。
- 多会话状态：气泡在并发会话间每 1.8s 轮播，刚完成的会话短暂展示「已完成」；失败/等待优先于运行中展示。

## 5. 加载、空状态与错误

- **Windows 快捷方式与自更新**：桌面、开始菜单和任务栏已有的 CC GUI 启动快捷方式使用固定安装入口及其图标，不绑定会被清理的 `runtime-updates/releases/<hash>`。正式 GUI 启动后由 `src-tauri/src/windows_shortcuts.rs` 在后台修复仍指向本 profile 版本目录的旧链接，保留参数、描述与自定义工作目录；更新成功或回退均由固定入口读取已提交状态。仅维护已有链接，缺少安装入口或使用开发 profile 时跳过；单个链接修复失败记录诊断并继续，不阻止应用启动，不新增弹窗或刷新按钮。

- 开发 profile 的中转启动失败由 `WebRelayCard.tsx` 沿用现有行内错误反馈；协议说明使用 `src/i18n/{zh,en}.ts`，明确要求 `ccgui-profile-v2`、独立 origin 与独立凭据。缺失、旧/未知协议或共享 origin 不显示连接成功，也不回落稳定入口；能力声明不作为身份认证证明。

- 整块区域加载：`CenteredSpinner`；有内容但空：`EmptyState`（都来自 `src/components/base/empty-state.tsx`）。列表局部加载用行内文字或 `Loader2`，不要动辄整屏转圈。
- 行内错误：`role="alert"` 容器 + `text-text-error-primary` 文案 + 明确的下一步（重试 / 关闭）。聊天页弹出横幅 `ErrorBanner`（`src/features/chat/components/ErrorBanner.tsx`，承载页面 `actionError`、会话 `sessionError` 及输入区 `imageError` / `branchError`）除手动点击 `×` 关闭外，无操作 `ERROR_BANNER_AUTO_DISMISS_MS`（5000ms）后自动消失；指针悬停或焦点位于横幅内时暂停计时，移出后重新计时，消息变更重置计时，卸载时清理定时器。回归：`ErrorBanner.test.tsx`。
- 警告与失败要区分：可恢复的失败给重试入口，不可恢复的（未安装、平台不支持）给说明或跳转，不给假按钮。
- **远程协作复用主机能力与授权**：通过现有 LAN token 或已批准设备连接的 Web 端可查看任务树、管理直属分支及使用主机允许的整组操作，也可处理计划审批、管理 MCP/Skills、调用插件已获授权的工具；不提供独立的协作模式开关。执行与配置始终位于主机；桥接操作逐次核对连接存活、设备批准代次，写操作核对浏览器来源，永久删除仍遵守本地主窗口约束。失效、权限不足、配置冲突与执行失败保留原有行内错误，不显示假成功。插件跨会话协调仍由桌面端单一消费者执行。
- **默认权限与 Codex 自动审查**：桌面端与 Web 在没有有效权限偏好时统一默认 `auto`，手动保存的有效模式优先恢复，不迁移或覆盖已有选择。权限菜单按 `EngineInfo.supportsAutoReview` 能力将 auto 显示为「自动审查 / Auto-review」，说明由官方审查器评估额外权限请求；其他引擎保留原有「自动」文案与能力回退规则。Codex 能力或受管权限配置不兼容时明确报错，保留诊断原因，不自动切换到完全访问。
- **自动审查记录**：官方 `auto_review` 事件按 `reviewId` 在时间线更新同一张只读卡，显示审查中 / 已批准 / 已拒绝 / 已超时 / 已取消，详情可折叠查看真实动作、风险、用户授权与理由；未知结果显示未报告，不冒充批准。完成先到、重复及晚到的开始通知不得回退已完成记录；停止、错误及孤儿回收将未完成记录取消。历史 `auto_review` 行沿用相同展示。事件按运行和会话身份路由，不写入当前选中的其他标签，不复活已结束运行；卡片没有人工覆盖自动审查结果的按钮。
- **Codex 权限人工处理**：官方少数需客户端处理的请求复用问答等待与回复通道，但以独立「权限审批」dock 和历史行显示真实动作、请求理由及结果，不作为模型提问。命令、文件和受支持的 MCP 请求只提供「本次允许 / 拒绝」；额外权限请求显示「本轮允许」，注明仅覆盖本次请求列出的权限、本轮结束失效。非工具审批的 MCP 表单、URL 或验证码请求明确拒绝，在会话警告中显示本地化说明并保留原生诊断原因，不显示成功。原生不允许批准时禁用允许按钮；无自由文本、永久授权或会话级扩大选项。提交中禁用按钮并防重复；失败保持待审、显示行内错误供重试，不伪成功。原生确认的允许 / 拒绝通过 `question_settled.answers` 同步桌面与 Web；无确认结果的取消按取消显示，迟到的本地回执不能重新批准已取消请求。回归：`auto-review.test.tsx`、`question.test.tsx`、`store/permissions.test.ts`。
- **远程主机路径授权**：Web 添加工作区使用主机绝对路径输入；工具访问未授权目录时，`GrantCard.tsx` 与桌面相同，展示实际授权目录范围并提供允许/拒绝。允许后调用主机授权接口并重试，保留失败反馈；远端输入与操作均针对主机文件系统。仍未桥接或依赖浏览器无法提供的原生能力，入口需明确说明，不能提供无效按钮。
- **子任务连接恢复**：初次加载、`task://changed` 及 Web 握手/重连后重新读取主机快照，收敛离线期间的分支变化；卸载清理事件与状态订阅。原有本地工作区、Claude / Codex / AGY / Cursor 引擎、直属父会话与删除约束一致适用于桌面和 Web。父子关系以真实 `branches` / `archivedGroups` 为准，旧角色标记不能建立任务组。
- **受信任会话的工具范围**：受信任普通本地会话及已登记的 worker 可使用 `task_spawn`、`task_list`、`task_wait`、`task_send`、`task_renew`、`task_stop`，无需先开启模式。公开 MCP 工具仅使用 `task_*`；旧 `leader_*` 工具已移除，调用拒绝，不转发或建立别名。能力响应使用 `taskTools`，不读取旧 `leaderMode` 字段。前端快照和管理 IPC 使用 `task_snapshot`、`task_branch_action`、`task_group_action`、`task_delete_branch`，变化事件为 `task://changed`。原生端继续核验身份来源、父子归属和权限，能力可见不替代用户对当前任务的授权。咨询已有会话沿用针对目标的明确授权，且不创建托管父子关系；共享自更新通道独立核验能力。外部 shell 启动、未登记的 CLI 不因工具名称或角色文本成为受托管子任务；侧栏空闲与历史暂未同步出回复都不能作为外部执行失败的依据。
- **双端工具与审批同步**：计划审批提交中、应用、冲突或失败回退后发共享失效通知，已打开会话重新读取主机记录；重连同时刷新工作区、会话列表和已打开审批。MCP 开关与 Skills 管理从原生命令广播变更，两端可见面板重新读取，部分变更后失败也需刷新且保留失败反馈。Web MCP 探测由用户显式发起；同步事件不自动重跑 Skills 联网搜索和仓库扫描。
- **远程 Worktree 控制**：查询、PR 解析、创建、取消及删除均在主机执行，沿用原确认和 Git 校验。进度向桌面与 Web 广播；主机保留全部运行项及最近 128 个终态的只读快照，初次打开与重连时读取。快照读取不消费结果、不重复创建，接管端不自动开聊天；旧快照不能覆盖新阶段。主机重启或记录淘汰后显示“状态无法确认”，核对实际 Worktree 列表，不把缺少记录当成成功或失败。
- **远程引擎管理**：Web 可查询版本、查看 CLI 安装/升级计划与实时日志、管理 Pi/OMP 账户和模型配置、查看 Claude 额度、控制主机 DSH 服务。CLI 每引擎只允许一次安装/升级，已有确认弹窗说明对运行会话的影响。每引擎最新运行快照及最多 200 行日志供重连读取，按 runId/sequence 归属和去重；子进程退出不等同整个安装完成，主机确认终态后才显示成功。重启后无法确认的尝试显示未知并允许关闭，不自动重发安装。配置变化通知只含引擎身份，刷新列表不覆盖未保存编辑稿。
- **CLI 更新必须核对实际生效版本**：桌面与 Web 的更新计划按当前使用的安装渠道生成；Windows npm 启动脚本通过相邻包文件识别，并将 npm 更新定向到同一安装前缀。安装脚本退出后重新解析实际使用的 CLI 并验证版本；无法读取有效版本、版本回退或未达到已知目标时显示失败，错误提供生效路径和版本信息，不把更新了另一份安装显示为成功。已经达到目标版本的重复更新允许成功。
- **远程插件生命周期**：Web 可从主机目录或市场安装、更新、启停、重载和卸载插件，沿用权限说明和卸载确认。主机保存状态并发变更事件，各前端读取后更新 UI/runtime；桌面跨会话协调仍只有一个执行者。卸载/停用使尚未完成的插件加载失效，旧异步加载不得重新激活插件；Web 自身的渲染失败只隔离当前浏览器，不把桌面插件全局禁用。
- **远程授权与导出闭环**：设置页展示并可撤销主机已授权目录，目录变化与重连重新读取。Web 导出部署包使用显式主机绝对保存路径，输入提示说明文件保存在主机；提交前确认可能覆盖，取消不写入，失败显示错误，运行中阻止重复导出。已有性能报告浏览器下载保持原行为。设备重命名、授权撤销、配对码轮换和复制失败显示行内错误及重试入口；轮换配对码不撤销已批准设备。
- 进度类反馈（安装、更新、同步）用 `Loader2` / 文字百分比表达过程，与 [§4.1](#41-刷新--重新加载转圈--对号) 的刷新反馈互不替代。
- **Worktree 创建进度行三态**：创建对话框即交即走，进度在侧栏「WORKTREES」分组顶部的进度行表达（`WorktreeProgressRow.tsx`，事件 `worktree://create-progress` 驱动）——进行中：`Loader2` + 阶段文案（校验 / fetch / 创建 / 注册，逐段替换）+ ✕ 取消（取消杀进程组、半成品 worktree 清理、已建分支保留）；成功：行消失、worktree 子行出现（勾选了「创建后打开新会话」则先清场再在该目录开新会话）；失败/已取消：行保留为 `role="alert"`（失败原因按后端 `errorKind` 本地化分类：网络/fetch 失败给重试，分支或目录冲突给改名指引，非 git 仓库/PR 不存在给说明，稀疏检出规则排除全部文件（`sparse_checkout_empty`）给修复指引），行内「重试 / 关闭」。三态行高一致，状态切换不推动其他行。
- **崩溃绝不留白屏**：应用崩溃时必须显示可读原因，而不是纯白窗口。三层兜底：`index.html` 的启动占位 + 8s watchdog（bundle 加载失败或 React 挂载前崩溃时显示失败面板与重载，原因读 `localStorage` 的 `ccgui:last-crash`）；`src/lib/crash.ts` 的 `error` / `unhandledrejection` 全局捕获；`src/components/crash/AppCrashBoundary.tsx` 顶层 React 错误边界。渲染崩溃页（`CrashScreen`）必须给出**具体错误原因**、可展开的技术详情、`重新加载` / `复制错误信息` / `退出应用`（Web 不渲染退出）；非渲染的全局错误在没有未提交的运行时恢复时允许「继续使用」后关闭。更新恢复失败时，`src/main.tsx` 解除页面 `inert`，使重载 / 复制 / 退出仍可操作，但保持任务提交与队列冻结；`AppCrashBoundary` 不显示「继续使用」，直到恢复已确认。弹窗、未保存草稿等只阻止生成更新快照；恢复快照时新挂载的界面不能要求用户在冻结页中关闭弹窗，恢复仍须通过参与者还原、事件回放及原生健康确认。环境性失败不弹崩溃页：浏览器自身噪音（`ResizeObserver loop`、`Script error`）与后台网络请求失败（断网 / 对端不可达，如更新检查的 reqwest `error sending request for url …`、fetch 的 `Load failed` / `Failed to fetch`）只记入诊断环，不上屏、不写入 `localStorage`（这类失败由各功能自身的错误状态表达，如更新行 / 浮层的失败与重试）。崩溃报告仅本地留存（内存环形 + `localStorage` 最近一条），不自动上传。
- **启动层资源必须是外部文件，`index.html` 里不得写内联 `<style>` / `<script>`**：打包链会给 `index.html` 里的每个内联标签打上 `__TAURI_*_NONCE__`，运行时把 nonce 追加进 `style-src` / `script-src`（`tauri-codegen` 的 `inject_nonce_token` + `tauri replace_csp_nonce`）；同一指令一旦出现 nonce，`'unsafe-inline'` 即被忽略，浏览器会拒绝**所有运行时创建的样式表**——插件的 `styles.css` 与 `ctx.theme.injectCss` 正是这样注入的，于是 v1.0.9 打包版静默丢掉全部插件样式，插件继续运行、无报错、不隔离（`plugin_list` 里 `lastError` 仍为 null），只有开发版看不出来（`pnpm dev` 的 HTML 不含 token，CSP 里没有 nonce）。样式在 `public/boot.css`、脚本在 `public/boot-watchdog.js`，两者都由 `style-src 'self'` / `script-src 'self'` 放行；回归：`tests/platform-build.test.ts`。

## 6. 破坏性操作

- 不可逆操作（删除、卸载、丢弃改动、断开授权）先确认：`ConfirmDialog`（`src/components/dialogs.tsx`），危险确认按钮用 `variant="danger"`。
- 由指针发起的行内破坏性操作可以用 `ConfirmPopover`，让确认贴近光标。
- 文案写清**后果对象**（删的是哪个文件/会话/插件），不写"确定吗？"。
- **退出应用**：窗口关闭按钮一律先确认（`src/lib/close-confirm.ts` 拦截 `CloseRequested`）；macOS 的 ⌘Q / 系统退出请求在存在进行中的会话时会被 `src-tauri/src/quit_guard.rs` 取消并复用同一弹窗，只有显式确认才销毁窗口退出，空闲时正常退出、不拦截。

Claude 上下文弹窗提供「窗口大小（K）」「保存」「默认」控件，范围为 100–1000K；保存时重新读取官方配置，只修改 `autoCompactWindow`，保留其他设置；「默认」移除此覆盖。写入成功后立即更新显示；失败保持原配置基准并显示错误。环境覆盖、自动压缩关闭或读取失败时禁用编辑并说明原因；保存期间禁用重复操作。这是全局压缩配置，模型实际容量仅在已知时单独展示；容量未知时，显式压缩窗口优先于 200K 默认估值，已上报、记忆或目录中的容量仍作为上限。

Claude 本机原生订阅渠道在输入框下方独立显示紧凑额度入口「5h 35% · 7d 剩余 38%」，与上下文占用和 750K 压缩窗口弹窗分开。缺失窗口显示「—」，真实 0% 保留；点击或键盘打开详情可查看各窗口的本地重置时间和倒计时，错误说明仅在详情出现。正常对话的有效额度更新触发通知，前端重新校验当前账号、渠道与项目后读取缓存；弹窗关闭时也能自动更新。挂载、获焦及每分钟检查只读缓存，不发起 CLI/API 查询。详情不放「更新信息」或「旧数据」标记。上次的 5 小时和 7 天数字一直留到下一次对话额度到达后再替换，详情记录这次更新时间。超过一小时或重置时间到达时不把比例清成横线。自定义 API 或远程工作区不显示本机订阅额度；旧渠道晚到的成功与失败都不能覆盖新渠道。通知中不传额度、账号标识或凭据。

Claude 后台工作进程在写入额度缓存后，通过任务事件流发送不含数值与身份的变更通知；主窗口收到后同步同账号的新缓存，无需结束会话或重启。获焦与每分钟检查也重读磁盘，兼容仍在运行的旧工作进程及错过通知的情况。同步保留原采集时间，同秒内不同的有效记录也能更新；更旧、其他账号、损坏或缺失的记录不覆盖有效内存，写入失败后重复读取已见的旧记录也不会倒退。

额度详情在已经拿到邮箱或计划时才显示对应行：邮箱使用 Claude Code 返回的登录邮箱（长邮箱换行），计划沿用官方显示名称。`setup-token` 没有资料权限，这两行和「未提供」占位都不出现。邮箱只出现在详情内，不加入常驻状态入口。账号/渠道切换及 IPC 身份校验失败会一并隐藏。不使用组织名推测昵称，不从模型或额度推测套餐档位。

退出后重新打开，首次原生缓存读取恢复经过当前账号、渠道与工作区校验的订阅资料和额度，不再因进程结束清空全部信息。恢复保留原采集时间：Claude 详情不把数据标成旧数据，超过一小时或窗口重置后仍显示上次比例，不补为 0%，并用更新时间表示这份数字的来源时刻；已经保存的邮箱和计划仍可展示。缓存仅保存在本机应用目录，认证元数据摘要不一致、格式损坏或版本不支持时忽略；不自动发起网络查询。首次使用修复版仍需正常取得一次信息，之后才有可恢复的记录。

常驻额度入口在百分比左侧增加紧凑重置提示，如「5h 23:49 重置」「7d 10/5 03:59 重置」。五小时同日只显示 24 小时时分，跨日补日期；七天始终带日期，跨年补年份。按本地时区和当前语言格式化，悬停可看包含秒数的完整本地时间，点击任一提示仍打开同一详情。缺失、已重置、快照过期或身份失效的时间不显示；百分比和时间使用同一有效快照，不新增轮询。状态栏右侧与额度按钮允许自然换行，保留时间、百分比和上下文控件；宽状态栏维持时间在百分比左侧。回归：`claude-quota.test.ts`、`ClaudeQuotaStatus.test.tsx`、`tests/browser/quota-status.html`（中英文 768/480/320 px）。

网络代理仅在「设置 → 网络代理」配置开关与地址；输入框下方状态栏不展示地球图标或快捷开关，也不为代理状态额外读取设置或订阅变更。新配置与缺失代理字段的旧配置默认开启，地址为 `http://127.0.0.1:7897`；已有显式开关和地址保留。开启后，新启动的 CLI 引擎、终端等联网子进程统一继承代理环境，本机回环连接直连；已运行进程继续沿用启动时的环境。

Windows 固定安装路径 `%LOCALAPPDATA%\Programs\CCGUI\ccgui-next.exe` 和正式 profile 的 `runtime-updates/releases/<manifestSha256>/ccgui-next.exe` 都在创建界面、拉起 worker 和联网之前执行启动保护：强制使用 `http://127.0.0.1:7897`，把 `NO_PROXY` 收成 `localhost,127.0.0.1,::1`，并写入 WebView2 代理参数。图形界面再核对本机 Claude 路径、代理预检、Claude 与当前实际 EXE 的防火墙边界以及 WebView2 策略；任一项不通过就弹出错误并退出，不打开窗口，也不改走直连。候选启动、提交后的重定向和保留版本的回退使用同一检查。开发 profile、其它路径的构建不进入这道门闩。`--host-chat-mcp` 等非界面模式不弹失败窗，但上述正式路径仍继承严格代理环境。已保存的设置不被启动过程改写；保护进程运行期间拒绝关闭或更改已审核的代理，并保留当前环境，避免恢复外部 `NO_PROXY=*`。

自更新每个候选 EXE 都需要独立的防火墙规则；固定安装路径的规则不能代替版本目录的规则。规则安装仍须 Windows 管理员授权，由更新准备步骤显式完成，应用只检查、不静默提权或写规则。缺少候选规则或候选不支持内置启动保护时，在进入更新事务前返回错误；正式切换前再检查一次，当前宿主和任务保持运行。

Codex 本机原生订阅渠道使用同样的独立额度入口与详情，标题为「Codex 订阅」。官方 `account/rateLimits/read` 和 `account/rateLimits/updated` 的额度窗口按 `windowDurationMins` 识别：300 为五小时，10080 为七天，不假定 primary/secondary 的固定含义，也不混合其他额度桶。账号未返回的窗口显示「—」，不会推算额度或补为零；账号与计划来自 `account/read`。首次挂载先读取缓存；原生明确返回 `not_loaded` 时，对新认证/配置上下文自动重验证一次，反复缺失不循环查询，成功后才允许下一次新上下文重验证。常规通知、获焦、分钟检查和连接恢复仅读已验证缓存；手动「更新信息」补充读取。后端冷却 120 秒，重置/过期、失败保留旧值与渠道切换的语义沿用订阅组件。查询只启动有界账号读取进程，不创建对话或模型回合；退出、其他认证模式或认证/配置元数据变更会使旧额度绑定失效，在途旧身份结果不得重新写回。同账号的 ChatGPT 初始化/路由就绪通知保留已验证额度与后续观测；空额度通知不覆盖有效缓存，也不刷新其采集时间。缓存不跨进程恢复，重启后重新读取；当前仅对可由本机 auth.json 元数据验证身份的原生登录展示缓存数据，API key、自定义渠道、远程工作区及无法验证身份的认证方式显示不可用，不展示其他账号额度。

Claude/Codex 的五小时窗口显示已使用比例，七天窗口显示剩余比例（`100 - usedPercentage`），常驻入口、详情及无障碍标签统一明确标注「剩余」。原生计数合约保持已使用百分比；只有经过有效期、重置时间和数值范围校验的数据才换算，缺失显示「—」，已用 0% 对应剩余 100%，已用 100% 对应剩余 0%。AGY 继续沿用已有剩余额度口径。

额度详情中每个窗口（5 小时 / 7 天）在文字下方增加细进度条，填充宽度与该行文字口径一致（显示已使用比例时按 `usedPercentage` 填充，显示「剩余」比例时按 `100 - usedPercentage` 填充），颜色仍按已使用比例告警（低于 75% 为蓝色、75% 起为琥珀色、90% 起为红色）；缺失窗口只显示空轨道，不补零。Codex 详情在窗口之后只读展示「点数余额」（官方 `rateLimits.credits`，余额文本经字符白名单校验，不限量时显示「不限」）和「重置机会」（官方 `rateLimitResetCredits.availableCount`，附最近到期时间）。**重置机会仅展示，GUI 不提供、也不调用任何兑换/使用入口**；快照不可用或过期时点数与重置机会一并隐藏。AGY 详情在分组之后展示「点数余额」，来自原生 `/credits`，与 `/usage` 并行读取、共用同一冷却，`/credits` 单独失败只隐藏点数，不影响额度，也不沿用旧余额。上下文浮层的「空闲 N」摘要与压缩/刷新按钮位于使用条正下方（左摘要、右按钮），分项明细仍在点击标题后展开。

Codex 上下文浮层提供「模型容量覆盖（K）」与「自动压缩阈值（K）」两个独立输入，100–1000K，留空使用 CLI 默认，压缩阈值不能高于明确设置的容量。保存及恢复默认使用窄原生命令，只合并官方 `config.toml` 中的两项设置，保留其他内容和注释，不读取或传送认证文件。渠道、选中 profile 或项目配置存在相应覆盖时显示原因并禁用全局编辑；远程工作区也禁用本地编辑。设置在后续 Codex 进程（通常下一回合）中读取，当前回合保留原配置；占用仪表继续使用 CLI 的真实报告，不以刚保存的值冒充当前有效容量，不承诺突破模型或渠道限制。挂载、打开浮层、获焦、设置变更及「刷新用量」重新读取，两项均可恢复默认。

AGY 上下文浮层提供前端自定义的「参考窗口上限（K）」「保存」「默认」控件，范围为 100–2000K（整数 token），保存在前端本地存储中，留空或点击「默认」恢复未设置。未设置时，优先使用原生已报告容量，其次展示已确认的模型目录或会话记忆容量；没有 `current_context` 时不据此声称实时占用，保留最近一次模型请求的 Token 明细，容量也未知时才显示「未知」；设置参考上限后，前端在原生容量缺失时以该参考值作为分母折算最近一次模型请求（或 `current_context`）的参考占比与进度条，并明确说明该值仅作前端参考、不改变 AGY CLI 实际上下文容量且不触发自动压缩。子任务健康检查继续只采信引擎真实上报的 `current_context` 与容量。

后台任务完成后，TPS 台账写入和晚到会话 ID 绑定通过该任务的事件通道通知界面，本地与远程窗口均自动重读。连接恢复时重新读取；同一会话的暂时读取失败保留上次成功的累计统计并显示错误，切换会话不保留其他会话的快照。Codex 恢复会话后，接收位于 `thread/resume` 回复之后、新回合生命周期之前的原生用量重放，冻结该线程的累计计数基线；新回合开始或收到确认后不再采用旧回合重放，多次模型请求按原生累计差值计数。基线缺失、计数冲突或中断仍显示不可用，不从文本、历史计时或单次请求的最后用量推算 TPS。Codex 额度观测通过后台任务日志传给宿主，仅包含已解析的额度窗口、原始采集时间和不可逆的身份上下文标识；宿主只更新仍匹配已验证登录的缓存。重连回放不改变原采集时间，旧观测不得覆盖较新的主动查询或账号失效状态。

注：Worktree **创建进度行不登记**在本清单——它不是「重新读取」入口，而是一次性任务的状态表达（进行中 → 成功/失败），用 §5 的进度语言（`Loader2` + 阶段文案），不存在「再刷一次」的语义；其失败行的「重试」是重新执行创建动作，同样不是刷新。

## 协作与子任务会话树

- **支持引擎**：Claude、Codex、AGY 与 Cursor 的受信任本地会话可咨询已有会话或创建真实子任务。AGY 模型保留完整原始 ID（含 `-low / -medium / -high` 档位）；管理视图只用明确的 `current_context` 报告计算占用，不以累计账单或最近请求代替。AGY 尚无原生压缩链路，因此不显示压缩建议。

- **Windows 工作区路径识别**：任务树与管理操作将同一 Windows 绝对盘符路径的正反斜杠及重复分隔符视为等价。不同目录、父子目录、大小写、末尾分隔符是否存在及 `..` 不合并；POSIX 路径中的反斜杠保留原义。

- **子任务模型设置**：设置 → 协作为 Claude / Codex / AGY / Cursor 各提供始终可见的三态文字按钮，区分不限制模型、仅允许所选模型、禁止该引擎新建子任务。使用 base `Button` small（32px），当前项采用 primary 样式并标注 `aria-pressed`，其他项采用 secondary 样式；窄窗口允许换行。兼容策略字段 `leaderAllowedModels`：引擎项缺失或 `null` 表示不限制，`[]` 表示禁止新建，非空数组仅允许精确模型 ID；别名、大小写和带档位后缀的 ID 不隐式等价。受限策略至少选择一个模型才可保存，空选不隐式变成禁用。三态切换保留草稿中的勾选，模型列表使用 `Collapsible` 的 200ms 高度过渡，收起后不接受勾选或键盘焦点。候选合并引擎目录、自定义模型、默认模型和已保存的选择；目录加载或失败不锁住策略选择，不改写草稿，已有选项仍可用。模型 ID 与长名称允许换行，控件有明确可访问标签，使用现有设置行、卡片与按钮样式。
- **模型范围保存与生效**：通过保存按钮提交草稿，期间禁用重复提交；读取/保存失败保留草稿并给出行内错误，不提示假成功，卸载后忽略晚到 UI 更新。保存基于最新设置合并模型范围，保留其他设置。限制仅影响后续新建子任务，咨询已有会话、主会话及历史子任务不受影响。未指定模型时，受限策略优先使用范围内的应用默认模型，否则使用首个已选模型；不限制时沿用应用默认或引擎默认。effort 可由创建请求指定，未指定时沿用该引擎的应用默认值，并按引擎支持处理。模型 ID/别名由对应 CLI 与渠道解析，选中不等于已验证其可用性；新建时仍检查引擎可用性。
- **两类协作**：咨询已有会话只建立通信记录，目标保持独立，不加入任务树，也不因咨询获得父子管理、TTL 或整组归档/删除关系。创建子任务产生本任务的新子会话及可恢复的真实分支；主会话负责当前任务的目标、授权边界、协调、验收与汇报。
- **普通首发**：已有会话和空白草稿均不提供独立模式的开启/关闭入口，不保存 `leaderOnStart`，不显示模式徽标。主窗口直接通过正常发送入口提交第一条任务，无需占位消息、重发或会话事件后的补授权调用；旧模式与专用首发 IPC 已移除。
- **首次身份与取消**：新父会话首次获得原生身份仍须验证本次运行的来源与绑定，能力位不能绕过身份校验。准备阶段可以停止或关闭草稿；取消、启动失败及晚到准备不得丢失未提交文本、附件、排队内容或下一轮输入，也不得重放已提交任务。
- **worker 权限与恢复**：已登记 worker 的父身份与权限在登记时冻结，完整 Interrupt 立即撤销该轮任务工具权利；恢复只接纳检查点中已登记的 token 与绑定，不从会话角色或用户参数重建授权。托管子任务暂仍由桌面进程持有，活跃时阻塞更新切换；重启后无法确认的分支保守标为 `unknown`，不自动重播。
- **停止范围**：停止一个直属子分支只停止该分支，不级联其子孙；完成或停止保留会话、结果和父子关系。模型工具不提供永久删除，用户删除及整组操作继续使用下述确认、空闲检查和原生隔离。
- 子聊天默认 TTL 按子引擎选择：Claude Code 60 分钟、Codex / AGY 30 分钟，显式时长优先；续期未填写时长时沿用该子引擎默认。已有分支的到期时间不因升级重写。侧栏可查看 TTL 到期信息，管理分支页始终保留完整到期时间，过期标记不替代日期。
- TTL 到期只提示检查，由用户判断是否压缩。已到期且有效上下文窗口占用达到 50% 时显示「可考虑压缩」建议；使用子聊天自身的可靠上下文读数与已知窗口，Claude 沿用配置的有效压缩窗口，Codex 使用当前上下文用量，不以累计计费量或运行时长推算。读数未知时明确显示未知，不触发高占用建议；建议仅提供信息，不自动压缩、停止、重派或删除任务。
- 侧栏以父会话为分页单位，子分支只出现一次并递归缩进；父行有独立箭头和直属分支数。展开状态按稳定会话/分支标识保存，选中后代时自动展开祖先和工作区。沿用 `SidebarDisclosure` 的 300ms grid 高度过渡、`aria-expanded` 与减弱动态偏好，行内按钮互为兄弟，不能嵌套。
- 只有真实未回收分支才建立可展开父子树；无子分支的旧角色标记不产生徽标、展开箭头或管理保护。已完成分支和结果保留在树中，明确删除后移出；真实子任务事件先于快照到达时可暂时保护子会话，随后尊重权威回收及归档状态。
- 「管理分支」绑定具体父会话，只列直属子分支，显示引擎、状态、检查时间、任务和结果，可打开已取得原生 ID 的会话。启动中无原生 ID 的行保留在侧栏，不进入会话搜索可打开结果；点击过期的启动中分支不得清掉当前中心面。后台子会话事件不得切换焦点、添加页签或借用用户草稿。
- 子分支隐藏普通删除/归档与悬停删除入口，右键可前往父会话，也可管理自己的后代。本地主窗口为未归档的子分支提供独立删除入口：叶子显示「删除此对话」，有后代时显示「删除此分支及子对话」，点击先确认名称、影响数量及不可恢复性；只删除所选分支及其后代，父会话和兄弟分支保留，不提升或遗留孤立后代。受影响子树有执行、排队、等待处理、启动、身份绑定、停止或回收中的成员时拒绝删除，不自动停止；确认时再次核对，原生端在同一准入锁下建立删除隔离。删除成功清理对应页签、缓存与晚到事件；部分失败只清理已确认为删除的成员，保留其余对话并显示错误。子会话仍不能单独归档。直属父会话可以续期或停止子任务；停止保留记录。模型工具中不提供永久删除能力，旧回收入口已移除。整组操作仍只由用户在根会话的本地主窗口管理视图发起。
- 续期默认按子引擎选择 Claude Code 60 分钟、Codex / AGY 30 分钟，可输入 1–1440 分钟覆盖。到期或空闲只是「需要检查」，不自动停止、删除或压缩；等待审批独立显示。已完成、失败、已停止的分支与结果默认保留，进程退场和删除对话是不同的操作。
- 「归档任务组」将一个根会话与全部未删除后代作为整体移出活动侧栏，不移动或删除原生对话、任务、结果及父子关系。归档管理中每组只显示一个入口，可展开查看分支关系与结果，恢复整组后回到原有树形结构。归档及恢复的所有成员标记由原生事务一次更新，不能借普通会话恢复入口拆开一组；归档不会创建永久删除墓碑。
- 「删除整组记录」是独立的危险操作，确认中明确包含根会话、全部后代、对话与结果，不能由归档操作替代。根会话右键同时提供「归档任务组」与红色「删除整个任务组」，均进入已有管理视图；删除还需点击管理视图的删除按钮并明确确认，不调用普通单会话删除，也不在菜单选择时执行删除。子会话、草稿、远程会话及 Web 不提供根任务组删除入口；处理操作期间入口禁用。只要根会话或后代仍在执行、等待人工处理、启动或绑定原生身份，归档与删除都拒绝，不静默停止任务；界面显示原因，用户可以先等待或停止任务。删除失败保留实际剩余状态与错误供重试，不报假成功。
- 归档或删除成功后一次关闭整组页签并清理本地缓存；当前页签属于该组时，按正常激活入口选择最后一个保留页签：冷缓存加载历史、引擎选择同步、草稿与模型设置保留，插件收到激活通知；没有保留页签则清空激活。恢复不自动启动模型或切换焦点。慢历史读取完成不得切回已归档或已删除的会话；永久删除仍由原生状态与事件墓碑阻止晚到输出恢复正文。

- **自开发工程目录（`ccgui-custom`）专属视觉标识、移除知情保护、设置重开与一键「构建并热更新」**：
  - **识别与持久化**：按 `live_update` 通道上报的 `sourceRoot`、本地持久化的自开发工程目录路径（`ccgui-next.selfDevWorkspacePath:v1`）及顶层 `ccgui-custom` 工作区回退规则识别 CC GUI 专属自开发工程目录，即使从工作区列表移除后仍保留路径记录。
  - **侧边栏显示优化**：自开发工程目录顶层行使用 `FolderCode` 工程图标（`text-status-purple-text`）、浅紫强调底色与 `自开发`（`Self-Dev`）胶囊徽标（已归档列表中同显徽标）；右键菜单额外提供「在文件管理器中显示」快捷入口。
  - **防误删与知情同意弹窗**：点击侧边栏移除按钮触发专属 `RemoveSelfDevWorkspaceConfirm` 弹窗，展示紫色「须知」卡片（说明该目录是 CC GUI 的专属自开发工程目录、移除不删本地磁盘文件、下次可在「设置 → 工作区 → CC GUI 自开发工程目录」或「设置 → 检查更新 → 运行中更新」重新打开），并要求勾选知情同意复选框后「确认移除」按钮才可点击。
  - **设置页重开与一键「构建并热更新」**：「设置 → 工作区」顶部常驻「CC GUI 自开发工程目录」分组卡片（搜索锚点 `selfDevWorkspace`），「设置 → 检查更新 → 运行中更新」卡片内同步提供快捷行，实时显示当前状态（`已在工作区列表中` / `已归档` / `已从工作区移除`）与「在工作区中打开 / 前往工作区 / 打开所在文件夹 / 更换目录…」动作；同时提供主操作按钮 **「构建并热更新」**（`settings-self-dev-build` / `live-update-self-dev-build`），即使当前无 AI 会话预先登记 `ready`，也可直接传入 `selfDev.path` 自动生成 `self-dev-manual-build` 后台增量构建批次并完成无感热切换（构建中显示旋转 `Loader2` 与「正在构建…」）。

- **可选启动代理保护与操作式功能引导（`OnboardingTourHost`）**：
  - **默认无强制代理保护（已部署环境自动沿用，普通用户可选开启）**：`AppSettings.launchProxyProtectionEnabled` 未显式设置时（`None`），由 `resolve_launch_proxy_protection_enabled` 自动判定本机是否已具备受审代理配置与本地保护脚本（`agent-assets/scripts/ccgui-firewall.ps1` 等）：已部署保护套件的机器自动沿用开启（`true`，自更新与启动门闩无缝衔接），新安装或普通用户机器默认不开启（`false`，不挂起启动流程、不联动 Windows 防火墙出站拦截）。用户可在「设置 → 系统 → 代理设置」按需切换「启动代理与防火墙保护（可选）」（搜索锚点 `proxyLaunchProtection`）。代理设置页顶部常驻提示横幅：若不清楚本机代理软件的 HTTP / SOCKS5 端口如何填写，可直接截图当前设置页面加上代理软件界面发给本机 AI 会话询问。
  - **围绕真实入口说明操作与效果（Spotlight + Popover）**：气泡保留主题切换，每项展示简短标题、1–3 条「怎么操作」和「会有什么效果」静态说明；移除自动轮播、三阶段标签及微缩演练沙盒。命令或普通提问提供可选中复制的输入示例，明确提交动作；不硬编码 Enter，沿用输入框提示的实际发送快捷键。标明高亮的控件名称；仅框可见的真实按钮、文字输入区或图片缩略图，找不到时说明前提，不以整个聊天区、输入栏或工作区组代替。设置导航后跟踪异步挂载并滚到对应控件；目标移除、禁用和尺寸改变同步更新，关闭时清理观察器与帧回调。气泡宽度上限 380px，小窗口限制高度并允许滚动；可通过 `×`、「关闭」或 `Esc` 退出。
  - **引导入口动作边界**：「前往输入框」只退出引导并聚焦，不填入、替换或发送草稿；点高亮图片或铃铛打开真实界面，已打开的旁聊/弹层不反向收起。「定位更新按钮」只聚焦，不触发构建；代理设置不会代用户修改或保存。禁用控件不执行动作并显示说明。图片进入原生预览后按说明继续批注，引导不模拟弹窗内部操作。
  - **8 个可选功能导览主题**：顶部提供 `role="tablist"` 主题切换栏，主题不自动前进：
    1. `proxy`（网络代理）：进入代理设置，开启「启用网络代理」，填写地址并点「保存代理设置」。高亮地址 input（不框整行）；地址格式示例中的端口须换成本机代理软件端口。
    2. `selfUpdate`（自更新与安装）：以高频使用的右下角更新管理入口为主，分 3 个手动步骤并显示步数。先高亮「自更新（N）」旁的列表图标，说明查看待更新改动不会提交更新，用户可关闭详情继续工作；再高亮自更新状态按钮，说明决定更新后显式点击才请求本批更新，等待任务/构建中/结果状态点击只查看详情。两处分别使用 `self-update-details`、`self-update-status` 控件锚点；引导中的定位只聚焦，查看详情可以打开真实详情页，不能代为请求更新。第三步才补充「设置 → 工作区 → CC GUI 自开发工程目录」的手动源码构建入口，高亮「构建并热更新」按钮。无已登记改动、提交中、源码目录缺失或客户端不支持时解释条件。
    3. `handoff`（Handoff 交接）：高亮文字输入区，示例 `/handoff 继续完成剩余任务`；必须在已有会话结束生成后、不带图片地提交，生成交接草稿后检查摘要、选模型并再次发送草稿。使用命令路径不默认归档原会话；不把仅在冷缓存等条件下出现的圆环交接菜单说成常驻入口。
    4. `sidechat`（Sidechat 旁聊）：精确高亮模型选择器旁的分叉按钮（`data-onboarding-target="sidechat-toggle"`），说明点击打开右侧独立问答、主任务继续、默认只读，再次点击收起且保留内容。气泡「打开旁聊」复用真实按钮并退出引导，已打开时不反向收起，不发送问题；按钮不在当前界面时隐藏该操作并提示支持的会话类型，不退回高亮整个输入框。
    5. `btw`（`/btw` 顺带一问）：高亮文字输入区，示例明确 `/btw` 后的空格和具体问题，须提交才触发；说明支持的四类引擎及主任务运行中可用，答案不写入主对话历史。
    6. `imageAnnotation`（图片批注）：有可批注图片时高亮其可点击缩略图，无图时高亮输入区提示先粘贴/拖入。说明点预览底部「批注图片」笔形按钮、拖出红框、为每框填说明、点「添加到草稿」，最后检查并发送。
    7. `assistantNotices`（助手与旁白）：精确高亮铃铛，关闭状态下在弹层开启；来源与语音在「设置 → 系统 → 助手与旁白」修改后保存。
    8. `intelligenceUi`（Intelligence UI 交互回答）：高亮文字输入区，提供 Claude/Codex 普通提问示例，明确无斜杠命令。生成卡片后调整参数，点「使用这些参数继续讨论」只带入草稿，还需用户发送。
  - **顶栏回顾入口与隐藏/重开**：左上角 `CC GUI` 品牌栏下方（`SidebarDragStrip` / `SidebarBrandRow` 及侧边栏收起时的顶栏前导位）提供胶囊按钮「功能引导」（`OnboardingEntryButton`），右侧附内联 `×` 按钮，气泡底部亦提供「隐藏不再显示」按钮；点击后隐藏顶栏入口（保存在 `ccgui-next.onboardingShowEntry:v1`），可在「设置 → 通用 → 外观 → 显示顶栏功能引导入口」（搜索锚点 `onboardingEntry`）随时重新开启或直接点击「打开功能引导」。桌面端首次启动自动弹出一次引导（记于 `ccgui-next.onboardingCompleted:v1`）。回归：`OnboardingTour.test.tsx`、`builtin-search.test.tsx` 与原生 `launch_protection` 单元测试。
