# 接力：规划 → 执行，双节点 SOP 设计草案

日期：2026-09-23。状态：等待交互稿评审；未开始正式插件实现。

## 结论与范围

可实现两类路由：同引擎不同模型、不同引擎交接。二者共用固定的规划 / 执行节点，各自配置 engine、providerId、model，不引入通用节点编辑器。同一引擎也可跨渠道；这不意味着会话必然兼容。

本目录只有独立 HTML 交互稿和规划说明；无依赖、无网络请求、无真实模型调用、无工作区文件读写。不修改应用业务代码。HTML 可以直接双击打开。原型的模型和渠道是示例，不代表本机已安装、已登录或真实可用。

## 已核查的项目证据

- `packages/plugin-sdk/src/context.ts:219`：ctx.agent.start 接受 engine、prompt、workspacePath、model、providerId、sessionId；interrupt 可中断本插件启动的轮次。
- 同文件的 ui.registerCenterTab / openCenterTab、storage、events 可承载插件中心页、配置与事件流。
- `src-tauri/src/plugin_caps.rs:217`：插件 agent 权限、属主 runId 和宿主引擎调用入口。
- `src-tauri/src/engine/mod.rs:559`：独立插件事件流；明确尚未开放 effort、permission、computer_use、图片参数。
- SDK 未提供规划只读工具策略与模型 / 渠道能力发现接口。不能把 prompt 中的“不要修改文件”当作安全隔离，不能宣称任意引擎都支持原地切模型或会话续接。

## 方案取舍

1. 推荐：插件独立页面管理一个 SOP run，下挂两个引擎轮次。复用宿主执行管线；交接、确认与状态持久化归插件，权限和能力验证归宿主。
2. 不推荐首版：接管现有聊天窗口、隐式自动切引擎。会话身份、历史归属、取消边界及聊天 store 耦合更复杂。
3. 暂不做：通用工作流画布、多分支、多 Agent 并行、第三个复核节点。验证属于执行节点，不新增节点。

## 用户流程

1. 打开插件中心页，选快速预设或独立配置两节点。
2. 输入目标；默认开启“由我确认再执行”。自动交接是用户显式关闭此选项后的选择。
3. 规划节点进行只读探索并产出结构化计划；未具备只读强制能力的引擎组合必须阻止正式运行，而不是静默降级。
4. 确认页展示目的引擎 / 渠道 / 模型和交接内容，支持编辑计划、重新规划、取消。
5. 确认后冻结配置与计划版本，顺序启动执行节点。执行阶段不得热改模型。
6. 执行输出改动、验证和限制。失败保留已确认交接包，只重试失败节点；取消不回滚已产生的文件改动。

交互稿“重新规划”仅重放固定模板；正式版应允许用户附带反馈后续接规划会话。交互稿不验证模型能力、不实际恢复后台任务；本地存储只保存默认配置。

## 交接契约

最小交接包：schemaVersion、sopRunId、planRevision、workspacePath、工作区基线标识（如 HEAD 与已有改动摘要）、原始目标、确认计划、相关文件与证据、禁止事项、验收项、目的节点配置。传递最小必要内容，不含密钥、隐藏推理和无关完整日志。

- 跨引擎：必须新建执行会话；绝不把 Codex sessionId 传给 Pi。
- 同引擎：首版默认新会话 + 交接包，一样支持更换模型和渠道。续接作为可选优化，仅能力探测通过后启用；否则显式告知回退。
- 冻结后工作区有外部变化：重新核对，不静默执行陈旧计划。
- 自动交接也必须校验计划结构、能力和工作区；结构不合格停在规划节点。不得将自然语言“完成”当成事件层成功。
- 手动编辑计划形成新版本；批准仅绑定该版本和节点配置。

## 状态与恢复

idle → planning → awaiting_confirmation → executing → completed。
自动交接跳过 awaiting_confirmation，但仍做校验与快照。
planning / executing → failed；非终态 → cancelling → cancelled。

每次运行使用唯一 SOP runId，每次尝试记录独立 attemptId 和宿主 runId。事件先按 runId 过滤，再按 seq 去重、排序；只有终态成功才可推进节点。处理中断时等待宿主确认退出，屏蔽旧尝试的晚到事件，防止重复启动。

首版同工作区最多一个写入执行者；跨插件 / 普通聊天的冲突需要宿主层协调，不能仅靠插件局部锁保证。重试执行前必须核对已有改动和上次工具副作用，禁止盲目重放。刷新 / 重启后恢复为“待核对”，不擅自重启执行。

## 实现顺序（本轮不执行）

1. 补齐宿主契约：可用引擎 / 渠道 / 模型发现、只读能力与 enforceable permission/tool policy；确认中断和终态语义。必要时增加查询未终止 run 的接口。
2. 插件基础：中心页、配置、两节点状态机、结构化计划、版本冻结、持久化。沿用公共 SDK，不直调未公开宿主内部接口。
3. 接入跨引擎新会话交接，再覆盖同引擎换模型；原地续接留待引擎兼容测试通过。
4. 补齐失败、取消、晚到事件、重复点击、重启恢复与工作区冲突处理。
5. 正式实现时同步国际化、UI/UX 规范；若修改 SDK / 权限，同步运行 plugin-skill:docs 并验证生成物。

## 验收矩阵

- Codex → Pi，Pi 强模型 → Pi 执行模型，同引擎跨渠道，能力不兼容回退。
- 未安装引擎、缺失认证、模型不可用、权限不足：规划前明确阻止。
- 计划失败不启动执行；空计划不可确认；编辑版本进入交接包；自动交接只启动一次。
- 执行失败只重试执行；取消后无后续启动；重复 done、旧 run 晚到事件不推进状态。
- 恢复时不重复执行；工作区变化使旧确认失效；跨供应商交接明确告知目的地。
- 原型验证仅证明 UI 状态流转，不替代真实 CLI、只读安全和文件副作用集成测试。
