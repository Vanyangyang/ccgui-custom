# 接力 v2：聊天内多轮规划与显式确认

日期：2026-09-23。设计交付，未开始正式插件实现。

## 核心决定

“本轮回答结束”不是“规划完成”。规划 Agent 可以反复提问、解释、修改，用户满意后点击最新版计划卡片的 **确认 vN 并执行**。这次点击是唯一授权边界，不依赖“好的”“开始吧”等自然语言判断，也不让模型自行批准执行。

两个 Agent 节点仍然只有规划与执行。界面中的“确认交接”是人为检查点，不是第三个 Agent。

替代上一版独立工作流主页面：入口放在输入框模型控件附近。启用后替换单模型摘要为“接力：Codex → Pi”；关闭后恢复原本单 Agent 配置。接力弹层可快速选择每个节点的引擎、渠道和模型。权限是独立控件，不把接力作为第五种权限。

首版暂不提供自动执行开关，避免在多轮探索中把“完成一次回复”误认为“用户同意方案”。未来若支持无人值守流程，应单独提供可审计的授权模式，而不是默认勾选。

## 丝滑流程

1. 首次开启：在输入框弹层配置规划 / 执行节点，关闭弹层后继续使用原输入框。
2. 规划阶段：输入框只向规划 Agent 发送。沿用它自己的 planningSessionId；模型轮次结束后回到可继续对话，不启动执行。
3. 普通解释不强制生成新计划；实际更新结构化计划才生成新 revision。本演示为便于体验，每条反馈都附加到新版本，并明确标注不是模型真实整合。
4. 计划卡片持续可见。用户可以直接继续发消息，不必先“拒绝”或“重新创建”计划；也可打开完整计划手动编辑。
5. 发出修改要求后，旧版不可再确认；等规划成功产生新版才恢复确认。失败时保留旧计划供查看，但不得执行未包含新要求的旧版。
6. 输入框还有草稿时，确认按钮禁用并解释原因，防止意见没发出去却提前执行。快捷建议不覆盖现有草稿。
7. 卡片内明确展示将要交接的引擎 / 渠道 / 模型。点击确认直接开始交接，不再弹第二个常规确认框；把必要告知放在确认按钮旁，而不是增加反复点击。
8. 同一对话中显示“已冻结 vN → 执行 Agent 接手”的记录。所有消息继续归属同一逻辑对话，但底层 sessionId 分离。
9. 执行时冻结计划、节点配置和权限，不再接收会改变本次任务目标的新消息。停止后可回到规划，带着实际执行结果重新讨论；先生成新版本再确认，旧批准失效。

## 计划内容与确认契约

正式版应接收结构化计划产物：goal、scope、steps、constraints、acceptance、openQuestions、sourceEvidence、revision、plannerAttemptId。

- openQuestions 未关闭、结构不完整、规划流未终止、工作区已变化或有未处理用户反馈，不能确认。
- AI 可以提出“建议进入执行”，但无权设置 approved 或直接启动执行节点。
- 用户点击绑定 sopRunId + planRevision + contentHash + configHash + workspaceBaseline。服务端校验后 CAS 状态切换，幂等键保证双击 / 重复事件只启动一次。
- 手动编辑保存为新版本，生成新 contentHash，不隐式授权执行。
- 聊天可见方案摘要必须与当前全文同源。原型初始概览对应示例 v2，用户手动编辑后卡片直接展示新全文，后续意见保留在该正文中，避免旧概览误导。
- 交接包含最终计划、原始目标、此前约束和决定、相关文件证据及验收标准；不只截取最后一条回复。用户提出又否定的内容由规划产物标记 superseded，不当作并列有效约束。
- 跨引擎 / 同引擎首版统一新 executionSessionId + 交接包。多轮规划则优先续接原 planningSessionId。两种续接语义不要混淆。
- 更换规划模型时按能力决定是否续接；不兼容则携带已有计划和讨论摘要新建规划会话。更换执行模型不重跑规划，但批准必须绑定新的执行配置。

## 状态与异常

规划内：ready → planner_running → ready；失败 → planner_failed。可以无限轮迭代，但历史版本与上下文必须有存储 / 压缩边界。

授权后：ready → handoff → executing → completed / execution_failed。

停止：handoff / executing → cancelling → cancelled。等待宿主确认停止，旧 attempt 的晚到事件不得覆盖取消终态。

返回规划：终态 → ready（旧批准无效、需重新核对工作区）。执行失败重试保留快照，仅重试执行节点；真实版必须先核对已发生的文件及工具副作用，不能盲目重放。

第一版限制一个逻辑对话只有一个活动 SOP，宿主同时防止同工作区其他对话 / 插件并发写入。恢复后显示“待核对”，不自动开始或重试执行。

## 工程实现边界

现有 `registerComposerSlot` 支持 cliMenu / permissionMenu 邻接入口；`ctx.agent.start` 支持模型、渠道和 sessionId。仅这些接口还不够完成聊天接管。

正式实现需要宿主公开：逻辑对话与工作区上下文、显式会话执行策略注册、发送与停止路由、双轮次时间线事件关联、模型摘要呈现、能力发现，以及 enforceable 规划只读权限。普通聊天和接力只能有一个发送消费者，插件禁用 / 卸载要安全恢复单 Agent 配置与路由。

不做 DOM 劫持，不伪造 CLI，不把插件事件未经归属映射就送进普通 chat store。规划提示词不等于只读权限。原型的“执行权限”仅示意，没有接入任何安全机制。

## 原型使用

打开同目录 `v2.html`，初始为已讨论两轮的计划 v2。

- 点输入框“接力：Codex → Pi”打开配置，尝试同引擎换模型或关闭接力。
- 点快捷意见，再发送；观察 v3 / v4 和确认按钮。
- 点版本记录，查看旧版只读与最新版编辑；保存形成新版本。
- 点“确认 vN 并执行”查看交接与执行状态；点击“查看本次交接包”核对完整快照。
- 顶部切换失败演示；可以重试规划、重试执行、停止和返回规划。

原型不发送网络请求、不读取工作区、不调用模型、不保存真实会话；刷新重置到演示 v2。模型名称、渠道、消息均为示例。静态侧栏不是导航入口。
