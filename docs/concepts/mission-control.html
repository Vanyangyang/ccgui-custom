这是一份借鉴 Sim 流程画布与 Paperclip / Multica 任务协作理念的原创概念稿，不是这三个产品的已集成版本。所有任务、审查结果、CI 与审批都为本地模拟；刷新即重置，无网络调用。

01 / 任务空间 · 你想完成什么

以目标为入口，而不是让人先画流程。任务持有范围、策略、负责人和运行记录。可以复用模板，也可以由自然语言生成草案后确认。

02 / 运行画布 · 现在发生了什么

流程模板是定义，30 个 PR 节点是执行实例。排队、执行、等待审批、失败互相区分。单节点失败不拖停整张图；缩放和详情抽屉帮助在全局与局部之间切换。

03 / 收件箱 · 我需要决定什么

同一事件驱动画布状态、通知和审计记录。审批不是一条聊天回复，而是绑定 PR、运行版本和 Head SHA 的操作；重复点击必须幂等。普通进度不打扰你。

生产实现中最关键的边界

  • 审查可并发，合并必须按目标分支协调，遵守 GitHub 分支保护和必需检查。
  • 审批后代码变化，原审批失效；合并前重新审查或重新确认。保留拒绝、撤销、失败和恢复路径。
  • 服务端持久化任务状态与队列；事件可去重、重放与断线恢复。画布不是调度器。
  • 大规模任务需节点聚合与按需展开；30 个节点不是性能上限验证。

本稿可以体验

节点详情、收件箱定位、模拟审批与拒绝、异常重试、并发调整、暂停调度、单步推进、模板 / 实例切换、结果记录、画布平移缩放。对话生成仅预览固定 PR 模板，不调用模型。
