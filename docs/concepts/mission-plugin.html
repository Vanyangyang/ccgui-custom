CC GUI / PLUGIN CONCEPT V2

不是另一个应用，是你的任务插件。

本稿基于项目当前侧栏、中心页签与插件 SDK 设计。仅是 HTML 交互概念，没有安装插件、连接 GitHub 或调用引擎；刷新恢复初始模拟数据。

入口：新建浏览器下方的「任务画布」

使用宿主同款导航行，不创建第二套工作空间侧栏。点击打开或聚焦唯一插件中心页签；原有会话、项目列表、浏览器与设置不变。

中心：插件自己的任务空间

页签内包含运行画布、待我处理、结果与记录。流程结构定义规则，运行图展开 30 个任务。通知定位节点，决策推动同一任务状态。

执行：借用宿主引擎，不挤占聊天

现有 ctx.agent.start / interrupt 与独立 agent 事件支持插件运行。规划中的调度、并发、任务存储、审批与 GitHub 合并策略由插件负责；不能把 UI 页签存在视为任务已可靠持久化。

源码已具备的扩展点

  • ui:sidebar-entry：注册侧栏入口；ui:center-tab：注册、打开与聚焦中心页签。
  • agent：启动和中断本插件的 Agent 轮次。独立事件流不混入聊天记录。
  • 主题 token、插件隔离边界、插件存储和设置入口可以沿现有机制接入。

概念与当前宿主的差异，必须明确

  • 位置：当前插件入口在禁用的「自动化」行之后。本稿按需求放到「新建浏览器」正下方，实施时需要调整宿主导航顺序或增加明确插入位置。仅靠插件 order 不能越过内建行。
  • 关闭页签：本稿演示关闭视图后任务不丢失、从入口重新打开。生产代码必须单独验证后台运行生命周期，并实现进程退出、应用重启后的恢复。当前中心页签列表是运行时状态，不持久化。
  • 通知：待办数量留在插件内部，不假设现有侧栏 SDK 支持独立 badge。宿主页签切换后的提醒卡也属于本稿说明性示意，不是已接入的宿主功能。
  • 合并：审批绑定任务与 Head SHA；合并前重验 CI、分支保护与代码版本。同一目标分支协调执行，不因模型说“通过”就直接合并。

侧栏入口、宿主页签切换、关闭 / 重开插件、深浅主题、模板 / 运行切换、30 个节点、通知定位、审批 / 拒绝、异常重试、并发调整、暂停调度、单步推进。所有宿主与插件行为均为模拟。
