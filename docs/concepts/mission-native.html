NATIVE / CONCEPT 05
AI AUTHORING / NATIVE WORKBENCH

AI 负责编排，人掌握目标和决定。

原生入口：「任务工作台」接替客户端原有的灰色「自动化」占位项，不再作为插件。本 HTML 仅展示目标形态，尚未修改应用入口或连接真实引擎。

流程定义：AI 生成读取输入、逐项处理、条件分流、人工确认、失败恢复与汇总的规则。人不拖节点、不连线、不手填节点配置；只能观察、定位并通过对话提出修改。

运行画布：本次示例展开 30 个 PR，最多并发 5 个。排队、执行、人工等待、失败和终结是不同状态。一个 PR 等待人工决定，不阻塞其他 PR 占用执行槽。

复杂度是真实的交互状态：PR 审查按“分析 → CI/冲突检查 → 风险分流”推进；高风险进入人工确认，低风险归档审查结果。失败按规则重试，超限后进入收件箱。所有分支终结后才完成汇总。

安全边界：本例只输出审查意见，不合并 PR、不评论、不访问 GitHub。人工介入指业务审批与补充信息，不是手工编排。排除某个 PR 会明确记入结果，而不是假装审查通过。

  • 首屏处于部分执行的快照：8 个完成、5 个运行、13 个排队、3 个待确认、1 个失败。
  • 下方按钮模拟执行事件，没有真实模型或后台任务。AI 修改由有限规则模拟；不理解的文字只保留，不会伪造能力。
  • 运行保存启动时的规则快照。改变草稿并发不会悄悄修改进行中的运行；下一轮才应用。
  • 不需要每个 PR 一个手写节点：模板中的 foreach 批量步骤在运行时展开为 30 个任务实例。
  • 所有状态仅在当前页面内存中；刷新重置。应用关闭恢复、持久化、权限与真实执行是后续技术方案待定事项。
