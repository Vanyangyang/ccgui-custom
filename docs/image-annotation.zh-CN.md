# 图片批注（方案，未实现）

状态：2026-10-19 方案稿，待确认后实现。来源是 Spellcast Canvas 退役评估：Canvas 实际只保存过 5 个对象（4 个法阵卡片、1 个骨架），批注数为 0。它真正值得保留的是「在图上指出位置，再精确交回原会话」这一点，所以只接入这一项能力，不重建画布。

## 要解决的问题

界面开发时，常见做法是截图后用文字描述「右上角那个按钮」「第二行文字」，模型仍要猜具体位置。GUI 驱动截图、生成图片和游戏美术资源的反馈也有同样问题。目标是让用户在图上框出位置并写批注，生成的内容只追加到草稿，是否发送由用户决定。

## 入口

| 期次 | 入口 | 现有组件 | 结果去向 |
|---|---|---|---|
| 一期 | 输入框附件预览 | `ConversationFooter` → `AttachmentLightbox` | 当前草稿 |
| 一期 | 聊天中的图片（用户消息、助手图片、Markdown 本地图片） | `ChatImage` / `MessageImages` | 该图片所在会话的草稿 |
| 后续 | 文件页图片预览 | `EditorFallbackViews` | 当前活动会话草稿（需明确目标会话） |

三处入口共用 `src/components/base/image-lightbox.tsx`。批注作为 lightbox 的可选模式加入，不另做查看器。

## 交互

- lightbox 工具栏新增「批注」按钮。进入批注模式后，在图片上拖动画矩形；每个框自动编号，在侧栏填写对应批注，可以修改或删除。
- 批注模式下仍可缩放和平移：按住空格或用中键拖动是平移，左键拖动是画框。框坐标按原图像素保存，与缩放无关。
- 操作按钮为「添加到草稿」和「取消」。如果有未添加的批注，按 Escape 或点关闭时先确认；按 Escape 时若正在编辑批注文字，只退出编辑，不关闭。
- 一次最多 9 个框；每条批注不超过 500 字，空批注不能添加。
- 视觉、动效和焦点规则遵循 `docs/ui-ux-spec.zh-CN.md`，落地时同步登记。

## 输出给模型

1. **标注图**：在前端用 canvas 把编号框画到原图副本上，导出为 PNG，通过现有的 `importImageFiles` 管道作为附件加入（存放在 `pasted-images`，沿用 7 天缓存清理）。原图不改动，作为附件并存，用户可以自行移除。
2. **草稿文字**：追加到现有草稿末尾，不覆盖：

```text
[图片批注] design.png（标注图为附件 2）
1. x 12%–40%，y 30%–52%：按钮文字被截断
2. x 70%–96%，y 4%–10%：图标和标题没有对齐
```

归一化坐标让不读图的流程和日志也能定位。当前引擎不支持图片附件（`supportsImages` 为 false）时，只追加文字和原图路径，并提示该引擎看不到标注图。

## 边界

- 只追加到草稿，不自动发送、不切换会话、不调用模型。来自聊天图片的批注只写入该图片所在会话；该会话不可用时明确提示，不写入其他会话。
- 批注不建持久库、没有版本或冲突协议，也不与外部服务通信。发送后，批注就是这条普通用户消息的一部分。
- 远程图片、读取失败的图片和非栅格图片（如 SVG）不提供批注入口，与现有图片预览的限制一致。
- 超出附件大小限制时，导出失败要明确报错并保留批注，不静默降级成只发文字。

## 不做

自由画笔和箭头（一期只做矩形）、多人协作、持久化批注板、回写 Spellcast，以及任何 Canvas 式的空间布局。

## 验证计划

- 单元测试：在缩放和平移状态下的屏幕坐标与原图坐标换算、导出图片尺寸、编号与文字一致、超过上限时拒绝。
- 组件测试：从附件和聊天图片两个入口添加到草稿；草稿已有内容时追加；引擎不支持图片时的降级；Escape 和关闭确认。
- 浏览器夹具：新增 `tests/browser/image-annotation.html`，覆盖明暗主题与高 DPI。
- 同一提交更新 `ui-ux-spec`，补齐 i18n 中英文。
